# 聊天搜索、表情包与主动消息（0.2.3）

本次交付是本地安卓版测试包，保留现有玻璃界面。搜索和表情包采用共享 Flutter 界面；
后台调度与系统通知本次实现 Android 版本。没有增加服务器、跨设备同步或真实外部执行渠道。
未提交、推送、发布 GitHub Release 或触发 GitHub Actions，等待用户本地测试确认。

## 使用入口

- 顶部放大镜：搜索当前或全部对话；支持翻页，点击结果查看前后各最多 12 条记录。
  结果摘要显示关键词附近的文字。只查本机仍然有效且同意保存的消息；不调用模型。
- 设置 → 消息 → 表情包：内置 8 张原创水滴角色插画，允许 AI 按语境自选一个或不用。
  可以导入 PNG/JPEG/WebP 等静态图片以及 GIF；静态图缩放到 512 像素，GIF 保留原动画。
  自定义表情最多 24 张、每张 2 MB；GIF 画布最多 512×512、最多 60 帧。
  图片与表情共用 48 MB 本地存储预算。导入时填写的含义帮助模型选择，图片不进入长期记忆。
- 设置 → 消息 → 主动找我聊天：默认关闭。开启后配置频率、免打扰、系统通知和通知预览。
  点击通知进入原会话，未读消息在对话列表显示数量。

## 主动消息规则

| 频率 | 尝试之间的最小间隔 | 每个日历日最多发送 |
| --- | --- | --- |
| 偶尔 | 12 小时 | 1 条 |
| 适中 | 6 小时 | 3 条 |
| 频繁 | 3 小时 | 6 条 |

这些是上限，不保证每次都会发。还必须满足原有最小空闲时间、授权和来源限制；
有一条主动消息未得到新的用户消息时，不继续发送。模型觉得不合时宜时可以选择不发。
失败或决定不发也记录本次尝试时间，完整冷却后才允许下一次调用，避免自动重试消耗额度。

免打扰按设置中的 IANA 时区解释，默认 Asia/Shanghai、22:00–08:00；开始与结束相同表示关闭
时间段限制。离线演示模式不会伪装成真正的后台 AI。需启用在线模型、聊天保存与模型调用，
并把 Key 保存在设备安全存储，后台冷启动才有模型凭证。一次检查最多一次主模型调用，
45 秒超时、384 输出 token，不开放 AgentLoop 工具或外部动作。

Android 使用 JobScheduler 持久化周期任务，每 15 分钟获得一次系统调度机会；网络、Doze、
系统配额与厂商省电会推迟执行，不是精确计时，也没有常驻前台服务。
Android 13 及以上需要通知权限；顶部提示还取决于系统通知频道和悬浮通知设置。
在红米上需要核对自启动、后台运行和悬浮通知；强行停止应用后需重新打开。
依据：[JobInfo.Builder](https://developer.android.com/reference/android/app/job/JobInfo.Builder)、
[通知权限](https://developer.android.com/develop/ui/views/notifications/notification-permission)。

通知默认只展示“发来一条新消息”，消息预览可以在设置中开启；锁屏公开版本始终为通用提示。
“测试通知”仅检查本机通知通道，不调用 AI。

## 数据与兼容

消息仍写入原 SQLite 记录。搜索不另建原文副本；通知队列只记录消息 ID 和已读/已通知状态。
主动上下文使用现有检索、偏好投影、来源引用限制和敏感信息过滤，记录依赖的来源 ID、
记忆内容哈希，发送前再次校验。来源被遗忘、更正、撤销授权或禁止引用后，待发通知不会
重新暴露旧内容；应用刷新或下一次后台检查会移除失效的系统通知。

表情包协议只描述媒体格式，不添加人物性格；自定义图片标签留在资料区，不成为系统规则。
媒体目录合并进原有背景资料，不改变真实对话的消息位置和人物归属。
自定义图片保存在同一 SQLite 备份里；删除图片后，旧消息显示“表情包已删除”。

UI 和后台 Job 共用一个串行原生执行器与同一个引擎实例。无界面时后台任务完成后停止自己
启动的引擎；界面仍持有实例时保留它。导入备份待恢复期间，后台不会代替用户触发恢复。
