# Magic-number policy

“魔法数字”是会改变产品行为、但散落在代码中且缺乏名字、来源或验证的数值。陪伴记忆中的保留期限、敏感上限、召回条数、字符预算和排序权重都会直接影响隐私与体验，因此不能隐藏在实现细节里。

## 唯一配置入口

行为参数统一放在 `companion_memoryos/defaults.toml`：

- `retention`：短暂、短期、长期、敏感和候选审核窗口；
- `retrieval`：候选池、条数、字符预算、时效半衰期和 CJK token 范围；
- `ranking`：六项评分权重；
- `continuity`：每种召回意图对九类记忆的连续性权重；
- `policy`：同意和敏感数据开关；
- `server`、`database`、`security`：运行参数。

部署方只写差异 TOML，加载器做深合并。配置模型会验证上下限、期限关系、权重总和以及完整的 intent × kind 矩阵。召回结果携带 SHA-256 配置指纹，便于还原一次决策使用的参数。

## 代码中允许什么

协议版本、单位换算、哈希长度和数学恒等值属于有名字的结构常量，集中在 `constants.py`。策略、评分和服务层只引用配置或命名常量。

`tests/test_no_magic_numbers.py` 使用 Python AST 扫描上述行为模块；除 `-1`、`0`、`1` 这些结构性值外，出现新的裸数字会让 CI 失败。新增行为参数时必须：

1. 在 `defaults.toml` 增加有语义的键；
2. 在 `config.py` 增加类型和边界验证；
3. 更新本文件与相关策略测试；
4. 通过配置对象注入使用点。
