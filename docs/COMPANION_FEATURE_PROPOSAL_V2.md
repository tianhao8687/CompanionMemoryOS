# 心隅功能方案第二版

调研日期：2026-09-26。本文是功能提案，待选择实施范围；所列新增功能尚未实现。

建议定位：保留水润玻璃界面，以用户设定为准，让角色说话稳定、记得共同经历，并能用文字和语音持续陪伴。

**参考依据**

本次参考官方功能说明及开发者发布的应用介绍，没有把宣传中的记忆准确率、情感理解能力当作实测结论。

| [Nomi](https://nomi.ai/) | 自定义背景、语音交流、可选主动消息、多角色及群聊 | 让主动联系接续已有话题，并保持角色背景一致 |

以下优先级和产品设计是针对本项目的建议，不代表这些产品都实现了同样的规则。

**当前基础**

已有自定义双方资料、头像和背景、聊天发图和识图、记忆查看与更正/遗忘、本地备份恢复。
0.2.3 安卓测试包又加入了聊天搜索、内置及导入表情包、结合聊天与记忆的主动消息、频率与免打扰、系统通知。
这些属于已有能力；以下涉及它们的项目均按升级安排。

0.2.3 的红米 K50 后台通知和真实模型语言体验仍待分别验收。Windows 本轮没有重新打包，不能将共享代码已有的功能视为已交付到旧 Windows 安装包。

**建议功能与实施顺序**

| 顺序 | 功能 | 用户可以做什么 | 范围与关键要求 |
| --- | --- | --- | --- |
| 下一版 | 语音消息（新增） | 按住说话、发送前查看和修改识别文字；听 AI 回复，随时暂停、重播；选择音色和语速 | 先做录音转文字与回复朗读。文字、语音共用同一会话和记忆；不默认长期保存录音。实时双向通话后续加入 |
| 下一版 | 角色卡升级 | 分别填写人设、关系、双方称呼、说话示例；保存设定版本，预览导入和导出，恢复旧版本 | 自定义角色不混入应用预设性格。性格、称呼、关系及表达方式发生冲突时以用户明确设置为准。版本恢复只改变设定，不篡改已发生的聊天 |
| 下一版 | 记忆手账升级 | 按“关于我、关于 TA、共同经历、待办约定”查看；标记重要、查看原聊天、继续更正和遗忘 | 沿用原有 SQLite 记忆和来源链。人物设定、日常事实、虚构剧情区分归属；标记重要提高检索优先级，不宣称每次回复都会引用 |
| 下一版 | 消息引用与收藏（新增） | 对某一条消息直接回复，把喜欢的文字、语音或图片收进收藏，回到原消息 | 收藏与“让 AI 记住”是两个操作，单纯收藏不自动扩大记忆使用范围；来源删除后正确清理或显示不可用 |
| 下一阶段 | 重新回复与编辑重发（新增） | 对最后一次回复选择“换一种说法”；修改自己的上一条消息再发送 | 保留可识别的版本；被替代内容产生的记忆和待发主动消息必须失效。完整历史分支在这条链路可靠后再做 |
| 下一阶段 | 共同回忆相册（新增） | 把一次聊天或一张照片保存成带日期的回忆卡；点击回看当天对话 | 图片文件仍是媒体，关联经过用户选择的文字说明和事件；不把模型猜测直接当成人生经历。相册沿用现有媒体存储与容量管理 |
| 下一阶段 | 约定、纪念日与主动跟进（升级） | 记录生日、纪念日和“明天面试”等约定；选择是否提醒、是否事后问候，取消或改期 | 复用事件与主动消息链路，继续遵守频率、免打扰和未回复限制。Android 后台调度可能延迟；精确提醒与 AI 问候应分别设计 |
| 下一阶段 | 一起做点事（新增） | 发起一段睡前聊天、专注陪伴、复盘今天或共同写故事，随时退出和换话题 | 活动只影响当前任务，不永久改变人物性格，也不新增永久“倾听模式”。计时器和界面不要求额外模型调用 |
| 下一阶段 | 私密空间升级 | 用系统认证解锁应用，导出带密码保护的备份 | 通知隐藏正文和设备安全保存 Key 已有；应用锁与加密备份属于新增能力，需分别验证恢复和失效处理 |
| 后续 | 实时语音通话 | 连续对话，允许打断 AI，切换扬声器或耳机 | 先验证延迟、耗电、断线恢复和费用，再扩展来电式互动 |
| 后续 | 多角色与故事分支 | 每个角色独立头像、设定、聊天和记忆；在同一故事上探索不同发展 | 先完成角色和分支隔离，再考虑群聊。共享哪些用户事实应由用户选择 |

**界面安排**

聊天仍是主界面。输入栏增加语音入口；长按消息打开引用、收藏及后续的重新回复。顶部头像进入角色卡，现有记忆入口打开记忆手账；相册与约定放在手账内。

设置继续采用通透分组卡片，保留统一玻璃质感和字号选项。语音配置、主动消息和数据管理各归其位。已有功能优先复用入口，避免把所有设置塞进聊天工具栏。

**建议先交付的范围**

下一版建议选定四项：语音消息、角色卡升级、记忆手账升级、引用与收藏。重新回复、相册和事件跟进作为下一批，实时通话、多角色群聊、3D 形象和公开角色社区排在后面。

这四项分别补足交流方式、人物一致性、记忆可控性和日常聊天操作。它们可以沿用当前本地应用架构，Windows 和 Android 各自保存数据，无需因这份功能方案先租自己的服务器。
语音识别、语音合成和 AI 生成是否联网及如何计费取决于接入的服务；本地保存聊天不等于模型完全离线。

**验收重点**

- 人物一致性：用户设定的性格、关系、称呼和表达方式不会被应用默认人物性格覆盖；更换说话场景不悄悄改变人设。
- 记忆一致性：语音识别文字在用户修正后再进入对话流程；同一事实可以找到来源、更正和遗忘；剧情内容不自动变成用户现实资料。
- 交互完整性：引用能够定位原消息，收藏重启后仍在；重要记忆的作用能被解释，不承诺绝对记忆。
- 数据连续性：安装更新后原聊天、图片、设定和记忆保留；备份恢复覆盖新增数据，模型凭证仍不进入备份。
- 安卓体验：红米 K50 分别验证前台、切换后台、熄屏和点击通知返回会话；区分通知权限问题、系统延迟和模型生成失败。
- 语言体验：使用另行授权的有界真实模型批次验证角色遵循和语音交流；离线测试不能替代这部分结果。

实施后沿用现有交付流程：本地检查与测试、提供安装包和结果、用户测试并明确同意后再上传 GitHub。本文本身不触发构建、上传或模型调用。
