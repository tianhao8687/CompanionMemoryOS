## 从使用体验看，变化在哪里

- “我喜欢”“你喜欢”“小王喜欢”不再共用一个主体。即使宿主误用了同一个稳定键，也不会互相覆盖。
- 新加坡凌晨问“今天”按新加坡日期检索；洛杉矶“昨天”覆盖夏令时切换的真实日界。
- 宿主不必自己把每句话写成 `MemoryInput`（记忆写入结构）和 `OpenLoopInput`（未完成事项结构）；只需保存原文并提交模型的候选解释。
- 模型抽取失败时，小事仍留在原始聊天中。解释不等于确认，未经确认的偏好不会被包装成当前事实。
- 多天的面试进展可归入一个事件；误归属可以纠正，正文和原始摄入凭据不变。
- “默默影响回答”和“已经对用户提过”分别记录，避免新记录机制导致每条熟悉记忆都被压制。

## 有意保留的边界

1. 不自带模型调用、自动抽取任务或提醒调度。解释接口是宿主模型与内核的连接点，不是完整聊天产品。
2. 候选不会自动晋升为长期状态。宿主仍需配置已有复核/纠正流程；这不是每件小事都向用户弹确认框。
3. 事件归属是轻量校验，不保证模型总能识别同一事件；没有固定天数阈值，宿主可以声明最大连续间隔。
4. 本轮回放使用人工编写的合成中文内容和固定模型输出，不证明真实模型抽取准确率、用户代入感或长期留存。
5. SQLite（本地数据库）的语义实现仍是精确扫描，不声称支持 100M（一亿）词元负载。旧备份彻底删除闭环也不在本轮冒充完成。
6. 没有自动上传、部署或发布生产版本。

20 个场景每个 32 条消息，共 640 条合成聊天消息，检查最终上下文里的原始证据、说话者、来源链接、词元预算和无证据状态。它们均已通过，但没有调用真实生成模型，不应解读为真实聊天回答或陪伴体验已经验收。
