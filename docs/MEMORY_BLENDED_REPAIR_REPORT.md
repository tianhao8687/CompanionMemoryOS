# 融合记忆修复与复测

日期：2026-09-25。范围：普通陪伴聊天中的记忆提取、检索、更新和遗忘。延续现有自定义人物，不增加固定问题配额，不靠删除回复里的问句改善评分。

## 修复内容

- 提取结果逐项校验。一项格式错误不再丢弃整轮其他有效提议；非法枚举、越界原文位置、缺失实体和错误引用依赖仍拒绝，不猜测补值。诊断记录被拒绝的字段路径。
- 原始用户话语加入实际向量检索，并可与结构化记忆同时使用。应用明确选择同一用户、伴侣、关系和群组内的跨会话检索；核心默认会话隔离不变。最终注入前继续检查来源、删除和引用限制。
- 普通聊天按多条证据完成任务，不再因为相关度接近、或者某个不相关偏好有不同描述而屏蔽整组证据。显式单一状态查询仍保留冲突判定。历史原话带时间、说话人和来源，不能自动当作当前事实或新指令。
- 综合安排行程时优先保留有日期的安排及更新，避免泛化情绪记忆挤走具体日程；区分“说出安排的日期”和“安排实际发生的日期”。显式时间筛选仍有效。
- 普通聊天收集原话时，不再对同一段经历只留一句。原安排、改期、取消可能属于同一经历，过早去重会丢失关键更新，甚至被随后过滤掉的助手话语占掉名额。默认核心事件检索的多样性规则仍保留。
- 明确取消、完成或改期可关闭旧的相关待办，并保留更新来源。临时的“安静几分钟”不再被模型的另一种分类复制为永久相处规则；当前聊天任务也不应自动留下长期待办。
- “钥匙换地方了，之前那个位置请忘掉”可追溯原始来源，即使原话没有成功形成记忆卡。关联回复和向量同步失效；回复是否能声称遗忘，以实际操作回执为准。
- 如果来源过滤隐藏了某条已完成的回复，保留下来的原提问会标为历史资料，而非继续作为缺少回答的原生用户消息。保留可用事实与来源限制，避免话题切换后重新执行旧计算。
- 关系上下文在生成前应用最新来源限制；不能只按该轮开始时间读取限制，从而漏掉同一轮刚执行的遗忘。生成后的提交校验保持有效，不通过放松来源规则消除报错。

SQLite 及原有证据、版本关系继续作为事实来源。遗忘是来源软删除与检索失效，不等于物理清除已有测试导出文件。本轮未迁移或批量修正日常数据库里的历史脏数据。

## 测试方法

使用新建合成数据库，经真实应用 HTTP、流式回复、模型适配器和存储路径测试。使用程序已配置的真实聊天模型和自定义人物；本机 `BAAI/bge-small-zh-v1.5` 提供 512 维向量。未附着日常数据库，未启用外部动作。

固定场景见 `tests/scenarios/memory_blended_repair.json`：28 次聊天、4 个会话、2 次真实进程重启。工作后的放松、同事谢礼、自己的饮品、周末安排、小说画面、预算变化、地点遗忘和拌嘴交织进行。评审元数据不发给模型。每批上限 32 次聊天、450 次适配器调用、每次 4096 输出 token、1800 秒，自动重试为零。

六次运行使用相同固定输入，各自从空数据库开始，是逐版回归重放，不是六组独立留出样本。以回复原文、最终模型输入、向量命中、SQLite 状态及遗忘回执共同判断；不把“回复非空”或“向量有命中”算作记忆成功，也不宣称官方基准成绩。v4 中途失败，未完成预定 28 次聊天。

## 剩余限制

已针对来源隔离、跨会话原话向量、部分提取依赖、显式状态冲突、临时偏好、改期取消、同一经历多条证据、已回答历史消息和无记忆卡的遗忘增加回归用例。

这轮小规模固定场景不能证明长期大规模记忆上限、任意日程表达、多人同名消歧或所有版本链均正确。部分模型提议仍会被拒绝；能通过原话补上回答，不等于结构化提取完全成功。v3 存储中仍有重复送礼待办和包含旧预算的摘要，不能据此宣称待办去重、所有历史版本已经清理。跨会话原话检索和每轮补建索引有预算限制，查不到不能推断用户从未说过。

v6 仍有重复谢礼事项、未随回答自动关闭的“核算账单”等待办，以及旧电影时间摘要。此次修复验证了聊天中的更新与取消，没有完成所有待办合并和关闭语义。最终真实批次关闭并停掉了自有测试进程，主程序及本地向量服务继续运行。
