# 聊天优先架构改造

日期：2026-09-29。目标是改善当前对话承接和记忆使用，不把产品改成长文问答系统。
本轮落实第一阶段：理解前置与统一最终上下文取舍；不声称完成全部长期规划。

## 已实施

1. **写入与召回拆分，先处理当前需求。** 原话存储、明确更正与遗忘先完成，
   复用已有 CurrentState 判断本轮目标，然后进行一次召回。
   原应用层先在内核查一次、处理本轮学习后再查一次的重复路径已移除。
   默认 `process_turn(request)` 接口保留同步行为，新增 Python 侧延迟入口，未增加 HTTP 授权入口。
2. **统一最终预算取舍。** 不再默认先逐条丢弃近期消息。
   普通聊天优先移除可选背景，然后才按完整来回裁剪较早对话；保留最近来回和明确引用来源。
   边界、当前明确要求、具体任务/回忆的已选证据受到保护，不靠扩大默认预算实现。
3. **去重但不丢来源。** 同一条原话已经在近期对话出现时，召回区只保留紧凑引用，
   正文不重复注入。匹配同时检查内容、角色、说话者和引用跨度，历史原文仍不是系统指令。
4. **摘要不代替细节证据。** 用户明确问过去发生了什么或要求完成具体任务时，
   经历摘要存在也不自动排除它引用的原始细节。普通聊天仍可用摘要避免无关原文堆积。
5. **采用计划与实际装箱一致。** 回应计划先预览，移除背景后重新计算，最终装箱完成才持久化。
   被预算移除的独立记忆不作为采用项进入发送计划；不因预览记录使用次数。

SQLite、身份/关系/会话隔离、同意、删除、引用限制和事实版本链保持原有约束。
延迟召回前后都检查来源是否失效或已有新用户消息；发送前的策略和来源检查保留。
没有固定问句配额、永久倾听模式、自然度后处理，也没有新增远程模型调用。

## 结论边界

- 现在可以验证的是处理顺序、采用的证据和预算行为，不是“聊天自然度提高多少”。
  尚未进行同模型、同人格、同预算的真实回复盲评，也未重新测量首字延迟。
- 不把消除重复召回直接换算成速度提升百分比；索引补建和模型调用仍可能主导延迟。
- 原有单次召回上限与最终聊天上限仍是两级限制；本轮统一的是最终取舍，未引入无上限候选窗口。
- 极端预算装不下必须保留的当前内容、最近来回、边界或必要证据时明确报错。
  没有用未经核验的摘要替换它们，后续可另行设计有来源的压缩策略。
- 暂未实现新的指代消解模型、跨天经历连接、后台向量补建或长消息语义分块。
  本轮指代承接依靠保留真实近期对话，不声称已解决所有指代歧义。
- 所有实际进程测试使用 `.agent-tests` 下的新建合成实例，不读取日常数据库。
  未推送 GitHub、上传原始测试数据或触发打包。

## 后续测试解耦

上述 19 项是当时的结构回归结果。随后审查确认其中存在预期读取生产映射、
预算夹具覆盖默认查询，以及手工摘要未覆盖完整经历路径的问题。
现已补充正常聊天入口的固定预期测试，并用错误注入验证其检错能力；
来源关联与细节保留也修复了新测试暴露的问题。后续还修复了写作请求的离线召回缺口：
明确任务的字面对象可独立参与原话词法检索，输出格式不再稀释该对象的匹配；
原题、置信门槛和来源约束保持不变，已移除对应预期失败标记。
具体方法与最新验证结果见 [测试解耦记录](TEST_DECOUPLING.md)。
