# 回忆小窝第一版：AI 原创像素物件

初版：2026-10-03；温馨像素画风与近看更新：2026-10-04。
本地源码功能，未发布安装包或上传 GitHub。

## 使用

网页聊天顶部，以及连接新版引擎的 Windows / Android Flutter 客户端顶部，新增“回忆小窝”。
打开后开启“让 TA 自动创作”，使用已经配置的在线聊天模型。可以继续正常聊天，也可以点击
“让 TA 布置一下”。离线模式不伪造创作结果，不会把固定物件冒充模型作品。

AI 先自主选择是否留下故事，交付物件名称、创作寓意、摆放区域和简短造型设计。
同一个模型再根据设计输出最多 16 色的调色板与分层绘画指令，本地程序落成 48×48 像素画，兼容已有
32×32 作品，不从预制物件库选图，
也不需要第二份绘图 Key。绘画指令是纯数据；不执行模型输出的脚本、不插入模型 HTML、
不读取模型指定的文件或图片 URL。已有逐行像素格式仍可读取。

物件可以放在窗台、书架、桌面、墙面或地毯。每区三个位置，冲突时寻找空位；区域已满时
原位置的物件进入收纳盒。用户可以查看创作来源，收起物件或摆回空位置。
收起不删除原记忆。已有物件可以由 AI 更新，时间轴显示现存、仍允许展示的物件历史版本。
收纳状态采用当前选择，第一版尚未重建过去所有收纳操作的完整房间快照。

## 自动创作与额度

- 新功能默认关闭；开启一次后，无需逐件确认。
- 完整聊天保存后触发独立后台创作，不在主回复中输出像素数据，也不运行 AgentLoop 工具。
- 默认每天最多 3 次创作尝试，可设为 1～12 次，按设置中的时区计日；同一本机库重启不重置次数。
- 自动触发至少间隔 30 分钟；重复消息重试不重复触发，同一来源快照不自动重复请求。
- 手动“布置一下”可以重新判断或显式重试，但不能绕过每日上限。失败和“没有新物件”也计入次数。
- 每次尝试最多两次模型调用：选材设计一次、绘制一次；没有新故事或设计无效时不调用绘制。
  两次均复用当前端点、模型与凭据，分别经过适配器调用预算，不自动重试或反复精修。
- 最多提供当前会话近期 12 条合格用户原话，以及 12 条当前会话或关系级合格记忆。
  单条正文最多 900 字符，来源摘要都作为用户资料传入，不进入系统规则。
- 每一步的小窝输入上限 7,500 token；每次调用非思考输出最多 4,096，思考模式可使用当前模型设置的额度，
  最多 65,536，绝不越过用户设置。思考也消耗输出额度；默认 4,096 对实测思考绘画不足。
  连接超时支持配置到 600 秒，默认仍为 120 秒；提高支持上限不会自动提高已有用户的设置。
  截断时明确提示提高模型输出上限，不自动重试，也不把半幅作品发布。
  完整输出仅漏最外层一个 `}` 时可补全后校验；其他无效 JSON、像素/指令错误、捏造来源均拒绝。
- 创作复用当前模型端点及凭据；可用性和绘画质量取决于实际模型。没有另接商业图像生成服务。

第一步返回带来源的选择和 `brief`（具体物件、可见结构、材质、故事细节），不预定绘图坐标、
像素尺寸或精确角度。四个字段分别限 100/240/200/120 字，防止设计稿变成另一份绘图程序。
若完整设计只漏了 `object` 包装，仅在所有字段通过同样的严格校验后接受；不补写设计内容。

## 2026-10-04：轮廓内上色与 48 像素兼容

当前新画稿明确输出 `size:48`、`outline:-1`。根级 `outline` 关闭强制全图描边后，
各层可选择不描边、单色边，或 `[亮边色,暗边色]`；左上用亮边、右下用暗边。
旧绘画不含这些字段时，保留 32 像素和最终一像素统一描边的旧行为。

新增 `clip` 画笔冻结当前图层轮廓和孔洞，后续高光/阴影不能涂到形体以外。
新增 `shade` 画笔按模型给定的横向或纵向分档色阶重涂已有像素，不添新像素、不填孔洞，

## 来源和生命周期

SQLite 仍是事实来源。小窝的物件、版本、来源引用和调用尝试账本存于同一数据库。
像素画和创作寓意属于记忆的衍生展示，不回写为用户事实，不修改人物设定。

只使用当前用户、角色、关系和允许作用域内的有效来源，沿用模型引用限制。普通原话需由
当前用户本人发出；敏感内容、撤销保存同意、失效或被更正的来源不参与创作。现实与剧情
的引用标签不能混合，剧情物件明确标注“故事里的纪念品”。标签与引用检查不等于已验证
模型对反话、转述或寓意的理解完全正确。

删除、失效或更正来源时，数据库触发器清理直接关联的物件及全部历史像素版本。
引用限制和过期资格在读取、生成前、发布前再次核查；历史回看不能恢复失效内容。
对正在生成的结果，所有输入来源都保留依赖，来源变化或设置变化会阻止发布。
第一版采用保守依赖：遗忘一项曾进入创作上下文的资料，可能同时移除多件受影响的物件。
这仅处理当前主库，不修改过去导出的备份或服务商已经接收的数据。

## 2026-10-04：阳光下的像素小窝

网页和 Flutter 都支持以下查看方式：
