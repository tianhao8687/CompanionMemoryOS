- `tests/test_chat_first_context.py` 保留顺序、来源失效、预算辅助函数等结构回归。
  意图预期不再导入生产代码的 `RECALL_INTENTS`；手工摘要用例明确命名为 composer 单测。
  删除按当前输出 token 数减 100、覆盖检索查询并关闭人物召回的旧预算测试。
- `tests/test_chat_context_contract.py` 通过 `CompanionAgent.chat` 写入历史、生成经历、
  召回、规划、装配和保存回复。生成端使用记录输入的离线替身，其他环节使用真实实现。
- 意图映射有独立列出的接口预期；中文写作请求使用三种说法，不从当前模型决策反推答案。
  目标名用于检查接口语义，不是要求用户在聊天里说出特定词。
- 预算固定为 5000 / 16000 token，分别测试压力场景和宽裕对照。
  同一段合成历史通过正常请求进入系统，不覆盖查询、不关闭人物召回。
  在模型接收边界用独立的 `cl100k_base` 调用检查序列化消息大小，不读取运行时计数结果。
  同时检查最近完整来回、最后的用户消息、持久化采用计划及使用记录。
- 从四轮真实聊天生成经历，再换会话提问。经历的摘要不包含原因细节，模型请求仍需保留
  真实来源原文；另外检查原生历史去重、遗忘、禁止引用和跨关系隔离。

这些是开发回归，不是独立留出集或自然度评分。输入原文一致性、事实和来源检查不是
对生成回复设定关键词、问号数量、固定问句配额或固定表达形式。

## 暴露的问题

初次运行 33 项，30 项通过、3 项失败，保留于
`.agent-tests/verification/decoupled-attempt1.xml`。
诊断发现前两种问法能找到原文，但经历只能通过预设主题词选入；写作问法也找到原文，
但置信度较低，采用计划将它抑制。

本轮作了两个生产修复，没有为新用例添加触发词：

1. 经历可通过已采用原话的来源关系参与选择，不再要求查询命中预设主题词。
   原有来源有效性、同意、引用反馈、作用域、敏感信息和预算检查保持生效。
2. 把本轮已有的细节需求传给 composer。即使证据使用模式为谨慎引用，摘要也不应
   把本轮所需原文遮掉。被禁止使用的证据不会因此重新加入。

测试解耦这一轮结束时，写作问法的低置信召回缺口尚未修复，没有修改原题、答案、历史材料或置信门槛。
当时 `test_writing_request_receives_the_reason_from_history` 将原要求保留为严格预期失败：
仅 `MissingTaskEvidence` 可被标记为 xfail，其他错误仍报失败；修复后会 XPASS 并使测试失败，
要求同时移除过时的已知问题标记。该项不计入通过项。
使用 `--runxfail` 单独执行该测试，仍真实失败，证据为 `decoupled-known-gap.xml`。
该缺口现已修复，过程和新结果见下方“写作召回修复”；以上保留为历史记录。

## 写作召回修复

同日后续修复保留原来的四轮历史、原题和原文断言。问题不是数据库中缺少原因，
而是写作请求中的输出格式稀释了整句词法匹配，导致正确来源被低置信策略抑制。

- 应用层从明确的直接任务中提取字面对象，供原话的词法候选检索与评分使用。
  输出格式仍保留在原始请求和最终模型输入中；语义向量、时间窗口、作用域、来源限制、
  候选上限和置信门槛不变，没有新增模型调用。
- 复用已有任务动词，不添加公司名、题目主题或答案触发词。引用、假设、否定、多操作和
  句法不明确时保留整句查询；不会把“预算”中的“算”拆成操作动词。
  这是保守的句法处理，不是完整中文理解或新的指代消解模型。
- 移除已知失败标记。新增不同事情和任务表达的正常聊天对照、只共享写作格式的无关历史
  对照，并把遗忘、禁止引用和跨关系隔离检查扩展到原写作问法。
