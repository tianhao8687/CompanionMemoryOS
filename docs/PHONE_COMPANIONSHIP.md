# 聊天中的手机陪伴

0.2.29 将手机设置接入当前聊天的工具循环；0.2.30 为屏幕调整加入环境光和接近状态。
用户一次性开启并选择范围后，主聊天模型
结合本轮表达与上下文判断是否调整，不要求每次下达操作指令，也不会按情绪关键词直接执行。
没有后台扫描聊天或全天候控制手机的服务。

## 陪伴范围

| 场景 | 可选择的动作 | 执行边界 |
| --- | --- | --- |
| 声音让人烦躁、想安静一会儿 | 小幅降低媒体音量 | 只在媒体正在播放、音量大于 1 时降低，最多约总档位的 15%；不调铃声或闹钟 |
| 疲惫想歇息、屏幕刺眼 | 结合环境轻微调暗屏幕 | 仅前台解锁、手动亮度、低光稳定且未疑似遮挡时，每次降低 20 或 40/255，最低 64/255 |
| 通知反复打断、想暂时不受打扰 | 优先勿扰 | 仅从关闭切到系统的 priority 模式；来电与通知仍按用户的系统勿扰规则处理 |

模型可选择最多两项，也可以只回应、完全不操作。单纯难过不等于应该开勿扰。
等待重要消息、驾车、开会、通话及明确只想倾诉时保持现状。原生音频状态也会拦截
通话期间的调整。歌曲选择继续由原有音乐陪伴负责。

## 开启与恢复

0.2.30 的「屏幕柔和一点」同时授权读取环境光、接近状态与调整亮度。升级保留原有权限，
新增读取权限不会自动放开；旧版已开启屏幕陪伴的用户可以关闭再开启这一项，界面会提示。
没有这两项读取权限时主动屏幕调整跳过，恢复已有调整仍可使用，不依赖传感器。

入口：「连接 → 手机能力 → 聊天中的手机陪伴」。默认关闭；首次开启默认仅选择媒体音量，
屏幕与勿扰分别选择。开启选定项目时，会把相应的读取与设置工具设为允许直接执行，
保留已有参数范围；点击、输入、长按等界面权限不随之开放。系统特殊权限仍由用户授予。
若随后把对应工具设为确认或关闭，主动陪伴会跳过，不弹出逐次确认卡。

用户说“别替我调整了”会在生成回复前持久停用主动联动。停用不会无条件改回手机设置，
下方仍提供「恢复陪伴前的设置」。也可在聊天中要求恢复；陪伴开启时，模型可在用户
缓过来或结束休息后恢复同一对话、最近 6 小时内的调整。它不承诺后台或到点恢复。

### 工作区新增控制（尚未打包）

- 默认联动间隔从 30 分钟缩短为 **3 分钟**，界面可选 **1／3／5 分钟**。
  旧配置缺少此字段时默认 3 分钟，已有开关和工具权限不变。间隔从上次尝试完成时计算，
  跳过的请求不会不断延长等待；它不是每隔几分钟执行一次的定时任务。
- 「暂停联动 15 分钟」保留已选范围、现有设置和恢复记录。暂停期间不主动调整或主动恢复，
  用户明确要求恢复、点击恢复按钮仍可使用。「现在恢复联动」可提前结束暂停；不会重开
  已停用的陪伴功能，也不会清空冷却。到期后仅允许后续聊天重新判断，没有到点执行动作。
  暂停截止时间保存在现有配置，跨重启有效。重新打开陪伴总开关会结束先前的暂停。
- 「保留当前设置」用于接受这次调整：不读写手机设置，只结束本次待恢复记录，
  原操作历史与冷却保留。未确认的调整不能保留；服务器校验页面提交的动作 ID，
  避免旧页面把后来产生的恢复记录清除。保留后不能再用本次恢复按钮取回先前值。

这两个控制只在设置界面提供，不给模型增加自行解除暂停或丢弃恢复记录的工具。
本轮源码测试结果与界面预览见 [短间隔与临时控制测试](PHONE_COMPANIONSHIP_CONTROLS_TESTING.md)。

恢复会先核对当前设置是否仍等于本应用上次写入的值；已被手动改变的项目保持现状。
亮度恢复包含原来的自动亮度模式。所有写入均携带刚读到的预期状态，原生桥再检查一次，
避免读写间的可见变化被覆盖。系统状态核对不能识别“改过后又改回相同值”的过程。

## 实现与验证边界

- `app_comfort_phone` 只接收场景、本轮原文片段与选定项目，具体幅度由代码限制。
  拒绝引用、转述、假设、历史陈述、无来源片段及明确任务语境，工具输出不能扩大授权。
- 实际操作复用 AndroidPhoneClient → ToolHub → droid-mcp。先检查权限、读取现状、
  保存原值、执行、读回；只有核对成功的项目可说已调整。
- 新增配置放在现有 `agent_config`；恢复信息位于同一 SQLite 的 `phone_comfort_changes`，
  不保存聊天正文。动作继续保留原有操作记录和来源链。
- 默认 3 分钟的可调间隔跨对话、跨重启生效；有未恢复或未选择保留的调整时不继续叠加。
  失败或结果不明不自动重试。已发布的 0.2.30 APK 仍使用原 30 分钟间隔。
- 主动权限只用于上述三种设置；不扩展到应用启动、界面点击、发送消息或支付。
- 自动化中的模型决策使用脚本模型，验证真实聊天、授权、存储和手机执行路径；
  不等于真实模型在自然对话中的情绪判断质量已经通过评审。

## 环境感知（0.2.30）

- 原样复用固定 droid-mcp v0.11.0 的 sensors 模块，公开 `get_light_level` 和
  `get_proximity`；SHA-256 记录在 `android/droid_mcp/UPSTREAM.json`，保留 Apache-2.0 许可证。
  不新增手机 HTTP 服务，也不需要安装另一个传感器应用。
- 模型依然根据本轮表达判断是否需要陪伴。选择 screen 后，先看系统亮度模式；自动亮度
  已开启或屏幕已较暗时保持现状。否则通过同一个 ToolHub 按需读取约 1.5 秒光照，再读接近状态。
- 所有光照样本都不高于 50 lux，且变化范围不大于 `max(5 lux, 中位数的 50%)` 才可调暗。
  中位数不高于 20 lux 时降低 40/255，其余符合条件时降低 20/255。这是待真机验证的保守
  工程阈值，不是医疗或跨机型舒适度标准。on-change 传感器只回报一个有效样本也可使用。
- 接近状态在桥接层按机型 maximumRange 校正，不直接沿用上游固定 5 cm 的判断。
  接近只代表疑似遮挡，不能确定手机一定在口袋里。无传感器、超时、无读数、过期、无效值、
  疑似遮挡或光线快速变化都跳过亮度调整；不会把未知读数当成 0 lux。
- MainActivity 的前后台生命周期约束读取；原生层同时核对亮屏、解锁，并在采样后再次检查。
  调整前还有前台检查、亮度预期值和 5 秒观察有效期。退出前台后不持续监听，上游采样器在
  正常结束、失败和取消时注销 listener。没有后台环境监控或环境变化主动发消息服务。
- 传感器数值进入现有工具操作记录，主聊天工具收到可用性与照度摘要；不增加独立的传感器
  历史数据库。不能根据照度推断情绪、用户是否睡着、具体灯具或整个房间的状态。
- 0.2.29 保存的待恢复设置仍支持恢复自动亮度模式；0.2.30 新的主动调暗不会关闭自动亮度。
