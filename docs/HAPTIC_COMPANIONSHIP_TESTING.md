# 触感陪伴接入与测试（2026-10-19）

## 随回复表达触感

按用户的新用途增加独立开关：`连接的应用 → 手机能力 → 随回复表达触感`，默认关闭。
开启后，模型结合当前对话，判断自己的回复是否有强烈的开心、感动、想念、心疼或在乎，
为自然说出的一句话准备触感，不按关键词、标点、用户情绪或情感浓度档位机械触发。
普通聊天可以完全不调用；工具说明排除技术说明、台词引用、争吵施压、恐吓和危机情境。
这属于提示约束；脚本模型测试不能证明真实模型的语义选择质量。

- `app_reply_haptic` 只准备本轮的一句回复。最终回复成功保存、运行完成且该句原样出现后，
  才经现有 ToolHub → AndroidPhoneClient → droid-mcp `vibrate_pattern` 下发短拍。
- 自动表达只用 `[0,80,200,80]`，共 0.36 秒，不循环；每轮最多一次，全局至少间隔 20 秒。
  动作记录在原有 SQLite 表内，跨会话及进程重启保留限频信息。失败也不立即重试。
  同一轮已有明确的震动或停止操作时，不再追加自动触感。
- 取消/生成失败/待确认/运行受限不触发，回复改变时丢弃未匹配触感，重试已完成请求不重放。
  当前版本在整条回复完成时触发，尚未实现逐字流式过程中与某个字精确同步。
- 开关只允许短节奏和停止工具，保留其他工具权限与参数限制；执行前重查开关、连接、
  工具循环及 `allow` 权限。改为确认/关闭触感分组会停用自动触感，不制造待确认震动。
- 说“别震了”“不要自动震动”“关掉随回复触感”会保存关闭；引用台词、条件句、否认指令
  不修改开关。纯情绪表达不能自行打开开关。
- 复用原生前台、解锁、未通话检查；没有更改 droid-mcp 上游代码或新增依赖。
  触感失败不替换已生成的聊天回复；系统接收指令仍不代表真机触感或陪伴效果通过验收。
- 触感准备不显示通用的工具执行状态提示；关闭开关时不注入触感规则和工具定义，
  避免占用原有对话的上下文空间。其他工具的状态提示保留。

## 原始按指令触感接入

当前源码复用固定版本 droid-mcp 的 `VibratePatternTool` 和 `CancelVibrationTool`，
增加触感陪伴分组。可以说“用短震拍我两下”或“用慢一点的震动节奏陪我缓一会儿”。
两下短拍为 0.36 秒，三次间隔短震为 4.64 秒，均不循环；可以停止本应用的震动。
开始时要求前台、解锁、未通话，停止不要求前台。Python 契约与原生桥都限定完整的两种节奏。
新连接默认逐次确认，旧连接新增工具默认关闭，需要在触感分组开启。
未将主动调节音量、亮度和勿扰的授权扩大到震动；纯倾诉不会获得触感操作授权。
系统接收指令不等于已感受到震动或情绪改善，结果显式标注未核验物理效果。
