# 聊天记忆优化与中文新题验收

日期：2026-09-29。项目：CompanionMemoryOS，实际应用：心隅。

本轮仅获准离线及隔离应用测试，未调用真实生成模型或 BGE，未读取日常数据库，
未推送 GitHub，也未运行旧 pytest 回归集或旧场景。

## 四项实现

1. **事实依据**：最终模型上下文增加来源权威级别、历史/当前适用状态、未知项、
   检索完整性及预算遗漏标记。历史用户发言不等于已成立事实，历史助手回复不等于
   用户证言，指代检索的来源不等于已经确定人物身份。原文仍为 user 优先级证据。
2. **中文承接**：显式引用和语法性回指可以使用同会话的原始来源扩展检索，保留
   当前用户原话。来源先经过同意、删除、敏感性、会话、现实层及过期版本过滤；
   依赖 ID 进入生成后的再次校验和回复来源链。没有新增题目人物、主题专用词表。
   目前仍是保守规则，不是完整中文指代消解模型。
3. **等待路径**：前台只编码当前查询，历史向量补建交给有界后台队列。
   一个批次最多编码 32 个输入，最多保留 8 个待处理作用域，相同键合并。
   未完成时保留 FTS，索引状态单独展示。关闭应用或重配会取消待办并收束工作线程。
   后台调用沿用原批次授权、原 trace 和持久化配额，不丢弃诊断授权，也不自动重试。
4. **长消息**：以标点及换行为边界切出最多 240 字的索引片段，检索时返回最多
   720 字的相邻原文窗口。SQLite 保存原文偏移、来源 hash 和派生向量，不复制第二份
   事实库；同一原文只占一个候选位置。引语位置随截取重定位，删除/更正使旧向量失效。

后台发布向量之前重新检查原始版本和来源限制。编码期间更正、遗忘、禁用来源或
切换编码器，旧结果不能重新入库。正文不变的 episode 元数据更新不清空有效片段。

### 离线检索

两套题均自行编写并在执行前冻结，没有采用历史测试题，也不是第三方标准基准。
题目断言不进入被测应用。首套在发现通用原文问题后复测，不能再称为盲测；
第二套在代码修复完成后另行编写、冻结，执行后没有按题目修改生产代码。

| 数据与条件 | 题数 | Top-1 来源命中 | Top-6 来源命中 | 返回候选精确率 | 所需原文覆盖 | 检索中位数 / P95 |

| 首套修复检查，冷 FTS | 18 | 83.3% | 100% | 84.7% | 100% | 67 / 113 ms |
| 首套修复检查，热本地哈希 | 18 | 83.3% | 100% | 77.3% | 100% | 86 / 134 ms |
| 最终新套，冷 FTS | 12 | 100% | 100% | 79.9% | 100% | 74 / 104 ms |
| 最终新套，热本地哈希 | 12 | 100% | 100% | 80.6% | 100% | 94 / 117 ms |

每题预先标注唯一相关原文及必需的原文字段。Top-k 以实际返回的 turn ID 计算；
精确率为逐题“相关候选数 / 返回候选数”的宏平均，不是回答正确率。
原文覆盖检查对应来源选出的片段是否包含所有预先登记字段。
冷/热使用同一组题，不能把两次测量当两倍样本。三道备用未知项题未在该离线
检索程序执行，不计入这 30 题；未知项标记另在真实进程和专项测试验证。

最终新套包含约 3,854、23,559、43,291 字原文，检查前段、中段和尾段。
长材料使用合成整理记录作为干扰段，难度不等于真实多主题长对话。这里只测
原文分块、检索及证据传递，不证明长文推理或总结能力。

本地哈希只是词法特征向量，不是 BGE。首套精确率下降，说明它会带入干扰候选。
不能据此宣称语义模型更强、整体准确率达到 100%，或真实模型回复变快了。

### 真实隔离应用

经网页 Cookie 握手、实例指纹校验，使用实际 HTTP 聊天、SQLite、上下文编排和
离线模型适配器；包括跨会话、真实重启、更正、遗忘、流式返回及存储 ID 核对。

| 批次 | 聊天请求 | 证据检查 | 单轮中位数 / P95 | 真实模型调用 |
| --- | ---: | ---: | ---: | ---: |
| 首套 | 21/21 完成 | 21/21 通过 | 147 / 430 ms | 0 |
| 最终新套 | 19/19 完成 | 18/19 通过 | 131 / 414 ms | 0 |

两批各有一轮按应用流程跳过检索，此时前台索引等待检查为不适用，不能据此
说实际执行过召回。其余证据、归属、来源限制与当前任务检查仍照常判断。
耗时取服务端 trace 的完整单轮时间，不含进程启动；P95 是小样本经验分位数。
这不是远程模型首字延迟，也没有修改前的同条件基线，不能计算提速倍数。

最终新套第 26 步未通过预登记的历史证据包含断言：请求给之前出现的人写感谢语时，
相关人物历史没有进入最终上下文。当前用户消息已包含收件人，因此不直接证明
写作回复错误，但暴露了“普通写作请求关联旧人物”仍偏弱。保留失败，不删题，
不靠新增人物名、题目词或降低阈值把结果改成通过。

离线回复是确定性演示，**真实回答正确率、自然聊天质量、少编事实的实际效果、
BGE 质量及真实生成速度均未验收**。没有把占位回复记作语言质量通过。

## 错误与留痕

- 新测试脚本最初误用了枚举名称，修正测试定义；长中文参数 ID 又触发 Windows
  环境变量长度限制，改用短 ID，测试内容不变。
- 首套离线执行暴露了实际错误：公共模型自动剥离 `evidence_text` 的尾部换行，
  原文偏移没有同步变化。已让证据字段保留原样，并新增独立验证。
- 首套应用的后置审计曾错误假定 `not_searched` 和正常召回使用相同字段，随后
  改为识别未检索状态，只重新审计已有证据，没有重复应用聊天，也没有删掉失败记录。
