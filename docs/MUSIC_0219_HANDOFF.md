# 心隅 0.2.19：直接打开网易云与自动歌词

版本 `0.2.19+22`，Android 安装包显示 `0.2.19-preview`，继续使用原测试包名与证书。

## 说想听歌就打开应用

新增内置 `app_open_music`，明确覆盖“我想听歌”“一起听歌”“打开网易云”。模型调用后，
实际唤起当前设备的官方网易云客户端，无需先选择歌曲、配置 MCP 或开启媒体会话权限。
这项固定应用快捷操作不修改现有 MCP 配置和操作权限，也不自动播放、暂停或切歌。
Windows 和 Android 的网易云 MCP 均新增 `netease_open_app`，已有内置连接自动刷新工具目录，
保留用户原有规则。工具结果与请求幂等继续使用原操作回执，重复请求不会再次启动应用。

Windows 使用已校验的 `cloudmusic.exe` 路径、参数数组及无 shell 的启动。
Android 使用固定 `com.netease.cloudmusic` 包的
[getLaunchIntentForPackage](https://developer.android.com/reference/android/content/pm/PackageManager#getLaunchIntentForPackage(java.lang.String))，
仅在心隅前台发起，并由 UI 线程执行；缺失应用或超时如实反馈。
启动应用不需要通知使用权；读取和控制播放会话仍遵守原有系统授权。

## Windows 进度丢失的根因

实际网易云客户端 3.1.41 的 SMTC 只返回主歌手，而窗口标题列出两位歌手。
原先用完整字符串相等定位播放窗口，导致补充的当前歌曲 ID、真实进度和总时长全部缺失。
现在允许系统返回的完整歌手名对应窗口中的歌手项，仍严格核对歌名/版本、进程路径、
客户端 DLL 指纹、前后窗口身份和歌曲 ID；不使用歌手名字的子串匹配。
原有 512 字节读取上限、不扫描、不写入进程等约束不变。

从最终打包引擎读取到真实位置 149,590 ms、总时长 222,000 ms；多歌手曲目 ID 与
服务端详情一致，并返回 53 行带时间戳的歌词。验证没有使用日常聊天数据库或真实模型。

本机网易云仍将 `is_playback_position_enabled` 返回为 false，时间线各字段为零，
也未向 UI Automation 暴露支持 RangeValue 的滑块。本版因此不能在心隅内拖动该客户端的进度。
界面显示真实进度，并提供可点击的“到网易云调整进度”，返回后重新同步。
没有将可读取播放时钟当成可写入播放位置。支持系统跳转的播放器仍使用原有进度拖动与回执核对。

## 两端自动匹配歌词

优先用播放器提供的准确歌曲 ID 获取详情，再核对歌名、歌手和已有时长，避免依赖搜索排名。
准确 ID 对应的歌曲可以只匹配系统提供的主歌手。Android 仅接受标准媒体 ID 中的数字 ID
或固定网易云歌曲 URI，不接受任意网址；字段说明见
[MediaMetadata](https://developer.android.com/reference/android/media/MediaMetadata#METADATA_KEY_MEDIA_ID)。

没有 ID 时使用现有歌曲搜索；缺少专辑名时，唯一匹配的歌名、完整歌手与时长可以自动选中。
相近时长仍限制在 2 秒内，Live、翻唱等标题版本不会归并。多个同样匹配的候选继续保留选择入口。
歌词网络请求不占住播放锁，换歌、结束活动或撤销连接时丢弃过期结果。歌词不会自动进入模型上下文。
