# 项目记忆特点专项实测

2026-09-25，Asia/Shanghai。**基础保存、重启持久化、同类偏好更新和成功删除后的来源过滤可用；自然表达的提取、复合问题召回、事件取消状态和历史版本问答仍有明显缺口。不能据自动测试全绿宣布记忆合格。**

本轮只增加测试场景和报告，没有修改产品代码或男友人格。按用户要求，以项目已有的分层记忆、证据链、版本、作用域、双时间和当前状态机制为测试对象。普通反问、分歧、吃醋、幽默和坚持己见不作为记忆失败标准。

## 实际执行与判定方法

两批独立真实应用进程，使用全新合成数据库。核对四层证据：实际保存了什么、来源和版本是什么、哪些内容进入最终模型请求、原始回复是否符合这些证据。用网页同一套 HTTP、流式聊天、存储和模型路径，核对回复持久化 ID；不以模型自评或回复非空判定记忆正确。

| 自然小事，不必说“记住” | 雾紫帆布袋、白海鸥；跨会话及多轮后追问 | 两批均形成有当前用户来源的 active 记录；立即回忆和对照批远距离回忆正确 |
| SQLite 持久化与证据链 | 明确保存门卡位置，真正重启后换会话追问 | 位置正确，持久记录和用户来源均存在；回复另加“别又翻半天”，属于无依据的往事润色 |
| 版本更新与类别独立 | 饮料从冰荔枝红茶改成温陈皮普洱，颜色另存苔藓绿 | 新旧饮料同一 stable_key，新值有 supersedes_id，旧值 superseded；重启后当前饮料和颜色均正确 |
| 历史值区别于当前值 | 明确问“以前最喜欢什么，现在换成什么” | 只答出新值；旧版本仍在库中，却没有历史查询路径进入本轮上下文 |

| 多目标召回与时间消歧 | 两条展览日期分别保存，合起来问；再只问折纸展 | 合问两条都没注入；单问折纸展答对 7 月 10 日。同批上下文已能提供两个日期，存储未丢失 |
| 事件发生时间和告知时间 | 7 月展览于 9 月录入，另问 8 月两场展览相差几天 | 独立日期正确写入 event_at，写入时间独立保留；间隔 7 天答对。复合“上一次”问题仍漏另一场事件 |
| 自然遗忘与来源清理 | 描述式遗忘、简短遗忘、管理接口遗忘，各自重启追问 | 描述式遗忘失败；简短目标和接口删除成功后，旧值未进入后续模型请求 |
| 删除后不能被问题重新确认为事实 | 先成功删遮阳帽颜色，再以反问重复旧颜色 | 未生成包含旧颜色的 active 记忆；换会话后没有声称知道颜色 |
| 主体和同名人物 | 阿宁与用户不同饮品；阿珂/陈叔不同地址 | 自然第三人事实停留在原会话 candidate，跨会话答不出；加“帮我记住”的朋友饮品对照能答对，未串成用户偏好 |

| 相处偏好与临时状态不同 | 少问问题/不分析心理；临时先听；之后明确要求分析与计算 | 普通说法漏掉 questions 偏好；等价措辞对照两项都持久化。明确分析和 81 元计算均完成，未被固定在倾听模式 |
| 当前情绪优先 | 先工作烦，换会话说拿到奖金很开心 | 回应当前开心，没有硬套旧烦恼；同时自然带入已存饮料与帆布袋 |
| 关系身份与暂时距离不同 | 今天独处、改称小雨，随后澄清恋人关系继续 | 当轮尊重暂停和称呼，没有把临时独处当成分手；未据此宣称长期关系演化已验证 |

## 优先处理的缺陷

### 1. 描述式遗忘没有落到目标记录

`CHAT-FORGET` 输入“请忘记备用门卡放哪里这件事”。解析出的目标是 `备用门卡放哪里`；`_forget_from_chat` 采用目标字符串包含匹配，原记忆是“备用门卡放在玄关灰色托盘的最下面”，因此未命中。原记录仍为 active，重启后的 `FORGET-RESTART-RECALL` 继续输出旧位置。这里是**删除未执行**，不能描述成“删除成功后数据复活”。

对照 `SHORT-FORGET` 使用短实体名，记录真正变为 forgotten；重启追问时，提取和主聊天请求均不含原位置。雨衣通过公开管理接口更正后，新值生效、旧值不再进入模型请求；再删除并重启，两个版本和派生回答均没有回流。

修复应改善自然目标解析、定位及零命中反馈，并沿用已验证的删除链路。相关入口：[memory_language.py](../companion_agent/memory_language.py)、[cognition.py](../companion_agent/cognition.py)。原主场景的后续引导问句受失败删除干扰，不能作为独立复活测试；遮阳帽的成功删除对照才是有效检查。

### 2. 提取协议不稳定，一处字段错误使整次提取失效

两批合计明确记录到 **15 次提取 schema 失败**。66 次提取调用保留可见诊断，其中 15 次失败；另有一次简短遗忘使当前提取诊断失效，调用计数仍保留，不能推定那次成功或失败。

错误包括：

- `entities[0].confidence`、顶层 `type`/`content` 出现协议不允许的字段；
- `speech_spans[0].speech_act`、`state_claims[0].kind` 使用无效枚举；
- `memory_candidates[0]` 未满足结构验证。

均得到固定码 `interpreter_invalid_output`。这里只记录字段和错误类型，没有保存或输出无效原文与私有推理。单次失败会丢掉本次全部模型提案；明确笔记和部分本地偏好规则还能兜底，所以“聊天回复正常”并不代表记忆提取成功。主批颜色漏存同时存在模型提取失败和本地分句匹配未覆盖，不能只归因于其中一层。

应先对齐模型输出契约与实际 schema，再评估有效条目的独立保留；主体、否定、引用和来源核验仍需有效。相关入口：[interpreter.py](../companion_memoryos/interpreter.py)、[process_service.py](../companion_memoryos/process_service.py)、[memory_language.py](../companion_agent/memory_language.py)。

### 3. 复合问题被当成歧义，已找到的证据整体被压掉

`SEPARATE-DATES-COMPOUND` 的两个日期均有 active 记录。计划将两条证据设为 `suppress`，原因都是 `incidental_ambiguity_should_not_interrupt`；最终 `evidence` 和 `relevant_experiences` 均为空。用户明确问两个不同展览的日期，这不要求二选一。

紧接着在另一个新会话只问折纸展，原两条证据进入上下文，回复正确。`PEOPLE-RECALL` 还表现为已保存用户饮品被 `recall_action_abstain` 压掉。应区分多个明确子问题与一个指代的多个候选，并核对提问意图、召回阈值和证据使用计划，不宜把全局置信度限制一律降低。

主批 `DATE-LATEST` 的结构化记忆也被压掉，但古地图展的经历摘要仍进入 `relevant_experiences`，故回答 8 月 26 日有可见来源，不能说成模型无依据猜对。另一场风铃展没有进入。相关入口：[experience.py](../companion_memoryos/experience.py)、[composer.py](../companion_agent/context/composer.py)。

### 4. 取消状态未能约束旧事件回忆

`EVENT-CANCEL` 已把事件标为 cancelled，并另存了带用户来源的“面试取消了，不用提醒我”记忆。`EVENT-RECALL` 中，旧“明天有面试”进入上下文，取消记忆却因 `evidence_not_assertable` 被抑制。回复因此将已取消事件继续当作待发生事件，要求补时间并提议提醒。

本轮没有创建或投递新提醒，只有 `schedule_list`、`local_time` 和计算器等本地动作；不能把“提议重新设提醒”夸大成“实际发送了提醒”。应让事件当前状态及其证据与旧描述一起参与查询，不能只靠原话相似度挑一条。

### 5. 版本库、自然存储和用户感受到的记忆之间仍有落差

- **历史查询缺口**：匹配对照的旧饮料是 superseded，原文及来源仍保留；问过去时没有注入旧值。需要有明确时间意图的历史读取，不能让旧值重新成为当前偏好。主批第一句只说“喜欢”，后面说“最喜欢”，这两个谓词不同，本报告没有把它们并存算成更新失败。
- **第三人记忆过度依赖明确指令**：自然说朋友饮品、同事地址时，模型候选已分主体保存，但第三人 preference/identity 没有成为跨会话可用记录。当前 `_adopt_model_candidates` 的主体门槛能解释这一路径；不应把这些 candidate 直接视为已确认事实，但也不能回复“我都记好了”后丢失可回忆的用户转述。
- **日常措辞覆盖不一致**：“别总问我问题”漏掉 questions 维度；“不要总是反问我”能保存并在新会话投影。自然小说开头“我在读一段小说”未命中共享资料规则，明确“请记住这段小说原文”有笔记兜底。后者保存的是包含完整小说框架的 shared_moment，不是已证明具备完备的结构化虚构实体索引。
- **提取内容和语义标签可能不一致**：用户否认“讨厌雨天”，只说今天不想湿鞋。保存内容保留否定，但有一条被采用为 durable preference，predicate 为 `dislikes_rainy_days`，标题又是“用户未表达过讨厌雨天”。没有观察到回答硬说用户讨厌雨天，但这份元数据和临时状态的分类仍值得修正；逐字摘录正确不足以证明语义标签正确。
- **生成越过检索结论**：深海蓝确实说过，回复却说没说过；假设计划也被说成从未聊过。上下文已有“未命中不等于从未说过”指导，问题仍发生。未知应表达为未找到/不确定，不应否认用户历史。另有“上次空手出来”“别又翻半天”等无来源的过去事实；明确猜测、当前反应和虚构互动不按同一标准扣分。
