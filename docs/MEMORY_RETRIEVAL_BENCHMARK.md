# 记忆召回、检索精确率与速度实测

日期：2026-09-28。结论适用于当前应用的**原话召回路径**。这次没有修改产品检索逻辑，也没有启用远程模型。

目前还不能称为稳定可靠的长期记忆召回：英文长对话的证据召回率约 36% 至 46%；中文小样本中，本地 BGE 找回了 16 道用户事实题的全部标注证据，但 5 道关于助手以往推荐/建议的问题全部漏召回。速度在几百条原话时为几十毫秒，在 5,000 条记录的合成负载上为几十至几百毫秒。

这些数字**不是最终聊天回答正确率**。原话已通过真实存储接口写入，再运行应用的真实召回、来源过滤和上下文预算逻辑；没有运行自动记忆提取、完整聊天生成或官方问答评分。用户所说的“正确率”在本报告中分别给出首条证据命中率和检索精确率，避免与生成答案准确率混淆。

## 指标口径

- **证据召回率 Recall@6**：每题前 6 条结果命中的标准证据数 / 该题标准证据总数，再对问题取平均。
- **首条命中率 P@1**：第一条结果属于标准证据的题目比例。
- **检索精确率 P@6**：前 6 个结果位置中属于标准证据的比例。空位置也计入分母。
- **至少命中一条 Hit@6**：不能替代召回率，尤其是需要多条证据的问题。
- **完整证据率 All@6**：该题全部标准证据均在前 6 条中出现。

例如一题只标注了 1 条证据，系统返回 6 条并正确找回它，召回率是 100%，P@6 只有 16.67%。未标注的内容可能仍有帮助，所以低 P@6 **不等于同等比例的记忆内容是假的**。本次按来源 ID 严格评分，不靠答案关键词出现在附近就算成功。

## LoCoMo 结果

每种配置均完成 1,527 次查询，共 4,581 次，执行失败 0 次。每个独立故事包含 369 至 689 条原话，5,882 是所有故事合计，不是每个用户的历史长度。

| 配置 | Recall@6 | 首条命中 P@1 | P@6 | Hit@6 | All@6 | 中位延迟 | P95 延迟 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 纯关键词 FTS | 46.34% | 28.88% | 9.23% | 52.13% | 42.31% | 27.60 ms | 32.62 ms |
| FTS + 现有 256 维字词哈希 | 46.18% | 29.01% | 9.22% | 51.87% | 42.11% | 49.29 ms | 56.19 ms |
| FTS + 本地 BGE 中文模型 | 36.02% | 18.34% | 7.30% | 41.13% | 32.29% | 75.08 ms | 85.33 ms |

现有字词哈希不是预训练语义模型。它在这一批中增加了耗时，召回率没有提高。本地 BGE 为 `BAAI/bge-small-zh-v1.5`，使用中文模型测试英文原题存在语言匹配限制，不能据此断言它在中文聊天中更差。中文检查如下。

下表为各类别的 Recall@6，仍然是证据召回而非答题得分：

| 类型 | 题数 | FTS | 字词哈希 | BGE 中文 |
|---|---:|---:|---:|---:|
| 单条事实 | 840 | 54.09% | 53.67% | 41.39% |
| 时间推理所需证据 | 320 | 57.68% | 57.68% | 45.70% |
| 多条证据推理 | 278 | 18.96% | 19.25% | 15.50% |
| 开放领域问题的对话证据 | 89 | 17.88% | 18.26% | 14.61% |

多条证据题的完整证据率只有 5.04% / 5.04% / 3.96%。其中 15 道有效题的标注证据本来就多于 6 条，在当前数量上限下无法全部返回；但这不足以解释其余大量漏召回。完整数据中没有发生上下文 token 预算截断，BGE 的 1,527 次查询均有非零语义匹配进入结果。

## 中文探索性检查

使用 MemoryBank 原始问题及完整历史，不翻译英文题。选择文件中的前 3 位用户，每位全部 7 题；是方便核查的小样本，**不是随机代表性抽样，也不是官方成绩**。证据 ID 由 Codex 在查看该组检索结果之前根据原始全文补标，没有独立真人复核；同义重复证据可能被低估。

| 配置 | Recall@6 | 首条命中 P@1 | P@6 | 完整证据题数 | 中位 / P95 延迟 |
|---|---:|---:|---:|---:|---:|
| 纯关键词 FTS | 71.43% | 47.62% | 13.49% | 15/21 | 15.17 / 23.45 ms |
| FTS + 字词哈希 | 54.76% | 42.86% | 10.32% | 11/21 | 19.80 / 23.07 ms |
| FTS + BGE 中文 | 76.19% | 42.86% | 14.29% | 16/21 | 29.74 / 34.26 ms |

BGE 对 16 道用户事实题的证据召回率为 100%，对 5 道助手历史推荐/建议题为 0%；FTS 和字词哈希也都漏掉了这 5 道助手原话题。BGE 比 FTS 只多完整找回 1 题，不能将这个小样本优势当作稳定统计结论。

### 助手原话的明确缺口

原始历史保留了 user / assistant 角色、时间、会话和回复关联。问到以前推荐过的画家、徒步地点、历史游戏，以及教过的减压或英语学习方法时，相关用户提问往往已命中，真正包含答案的助手回复没有进入最终召回结果。

代码位置与实测一致：

- `companion_agent/cognition.py:503`：候选经过来源校验后，常规结果只保留 USER 角色。
- `companion_agent/recall_completion.py:289`：历史助手回复只在 `PAST_REPLY` 命中时尝试补回，还要求关联到特定类型的历史任务。
- 本批 5 道失败原题都未命中该入口的正则；这解释了本批原话路径的确定漏召回。

这是原话召回层的发现，没有据此宣称完整应用所有其他记忆层和最终模型回答必然失败。本轮保留现状，没有边修逻辑边替换基线成绩。

## 数据量与速度

单客户端顺序查询，每个大小/配置固定 30 个问题。下表均为中位 / P95 毫秒。

| 同一检索范围内的原话数 | FTS | 字词哈希 | BGE 中文 |
|---|---:|---:|---:|
| 100 | 18.26 / 24.66 | 22.27 / 24.56 | 30.58 / 36.74 |
| 1,000 | 31.49 / 35.88 | 65.81 / 71.64 | 102.17 / 115.64 |
| 5,000 | 71.15 / 79.23 | 230.95 / 242.75 | 362.07 / 390.70 |

为了单独测规模，这一批重复公开对话原话增加 SQLite 记录数；是**合成容量实验**，不报告其召回/正确率，不代表真实用户有这些重复历史。原文向量每条只生成一次，重复写入时复用；表内查询向量每次重新计算。计时不包含建库/入库，也不是并发吞吐量或冷启动测试。

现有 SQLite 向量索引执行精确扫描，记录量增大后查询明显变慢，与代码实现一致。几百条历史的速度可以接受，不应直接外推成数万条记录仍保持几十毫秒。

## 测试边界与环境

- Windows 11，Intel Core i5-14400F，10 核 / 16 线程，Python 3.12.14；BGE 使用本机 CPU、4 个推理线程、现有模型缓存。
- 代码基线 Git HEAD：`48b76a39c5fac770b98f4379fd54197ad2b88192`。主批源码 SHA-256：`18c43fff1533cf6d88c5e3b168aa8a109861c29fb14fbeda32e1b884ad29fe86`。
- 通过 `ApplicationMemory.append_turn` 写入，使用 `ApplicationMemory.recall` 检索。保留当前应用的候选补充、身份/会话范围、来源检查以及 6 条原话、2,500 token、12,000 字符预算。
- LoCoMo 两名人类说话者使用不同 actor ID，均作为 USER 角色原话导入；每个故事/配置建立独立数据库。每个原始会话独立，查询来自同一关系下的新空会话。
- LoCoMo 只索引原话及数据自带图片描述，不读取图片，不导入生成摘要、人物画像、问答或标准答案。证据 ID 只用于评分。中文集保留助手角色，不把助手的话冒充用户事实。
- 时间取原始对话日期；数据未给时区，评测统一解释为 UTC，查询时点取最后一段历史之后一天。没有改变操作系统时间或冒充真实跨日使用。
- 延迟包括查询编码、SQLite 检索、应用召回过滤及提示上下文组装。BGE 直接调用同一个本地编码器，未经过 HTTP 包装；不含提取、索引刷新、聊天 HTTP、主模型生成或工具执行时间。
- 全程没有远程模型调用或自动重试，没有接入日常数据库、真实渠道和外部动作。模型权重截断上限为 512 token。
- 英文基准与中文抽查都只是原话层检索。没有得出最终回答准确率、自动提取成功率、遗忘/更新端到端成功率或拒答准确率。最终回答评测仍需按项目约定显式授权有预算的真实模型批次。

## 复跑

先下载固定版本，只把文件存入测试目录：

```powershell
New-Item -ItemType Directory -Force .agent-tests/recall-benchmark-sources | Out-Null
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/snap-research/locomo/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/data/locomo10.json' -OutFile .agent-tests/recall-benchmark-sources/locomo10.json
```

默认两种配置完全离线，不使用语言模型：

```powershell
.\.venv\Scripts\python.exe -m companion_agent.testing.retrieval_benchmark --dataset .agent-tests/recall-benchmark-sources/locomo10.json --modes fts hash --timeout 1800
```

本机已有 BGE 缓存与运行库时复跑三组：

```powershell
.\.venv\Scripts\python.exe -m companion_agent.testing.retrieval_benchmark --dataset .agent-tests/recall-benchmark-sources/locomo10.json --modes fts hash bge --runtime-dir .agent-data/embeddings/runtime --timeout 1800
```

中文和规模补充脚本位于本机 `.agent-tests/run_memorybank_cn.py` 与 `.agent-tests/run_retrieval_scale.py`。两者分别先冻结题单/标注和规模计划，再执行；不要在其他重负载检查同时运行时比较延迟。所有批次失败和成功证据均保留。
