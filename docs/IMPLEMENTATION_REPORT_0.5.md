# 0.5 体验层实现报告

日期：2026-09-01。状态：本地未发布，待集中验证。

本轮按“实用和感受”继续实现，不再只扩展记忆的数据分类。保留此前未提交的工作，没有提交、推送或创建新的远端版本。

## 本轮写入的主要能力

| 用户会感受到的变化 | 本轮实现 |
|---|---|
| 被理解，而不是被反复提醒“我记得你” | Memory Use Planner：无声影响、自然引用、明确回忆、必要消歧与抑制 |
| 难受时不会突然被盘问旧事 | 当下优先；非回忆问题的偶然检索歧义不生成澄清拍 |
| 面试、复查等事情有后续，但不会一直被催 | OpenLoop 状态机；相关性、明确时间、用户重新开启与等待回复逻辑 |
| 说一次“不是那个”能改变后续行为 | Memory/Event/Turn 通用反馈；已知原文—派生记忆血缘抑制 |
| 同一个梗不会每轮都被提起 | 已发送证据账本；默认以完整 conversation scope 去重，不使用固定冷却天数 |
| 中途改口后旧回复不再继续排队 | 回合写入与旧计划取消同事务；延迟完成的旧 trigger 不能重新建计划 |
| 不适合多气泡的渠道只收到一条 | 单消息编排合并；补充拍默认关闭，启用后仍需宿主释放信号 |
| 小事不必先成为记忆卡才有检索和纠错入口 | 原始回合多 key、可选向量、episode 级候选去重和原文反馈 |

新增 `experience.py`，并接入 schemas、config、SQLite、service、HTTP API、CLI 与用户导出。数据库版本为 v6，兼容 v5 及更早迁移路径；默认 Policy Bundle 更新为未校准的 0.5 alpha。

## 这不是完成效果验收

本轮只做代码与文档编辑、静态阅读，编写了集中验收用例，**没有运行 pytest、Ruff、mypy、构建、CLI smoke 或性能测试**。没有使用模型调用验证实际中文聊天效果，也没有上传。

之前的 `VALIDATION_REPORT_0.4.md` 记录的是 0.4 当时的结果，不能套用到当前工作树。因此不声明 0.5 已通过、不提供虚构的新通过数量，也不宣称召回准确率、token 成本或延迟已经改善。

## 必须如实保留的缺口

1. **自然语言接入仍未闭环。** 宿主需要识别“只想倾诉”“不是那个”“已经考完了”，选择目标引用并调用接口；这版没有自动话语解释器或最终聊天界面。
2. **计划不等于实际分段聊天。** 内核不调用聊天模型、不发送消息；当前计划生成仍同步检索，尚未获得异步首拍的时延收益。
3. **发送回执不能撤回已发送内容。** 事项版本、顺序、取消和策略检查是数据库契约；最终渠道仍需要发前检查、outbox 与原子发送协调。
4. **长尾语义仍依赖索引覆盖。** 没有 key、没有向量、词面也不同的旧事，不保证找回。当前向量仍线性扫描，episode_id 依赖宿主，前置候选挤占问题未完全解决。
5. **还没有日历或真实提醒。** OpenLoop 能记住待跟进事项，不等于设置了通知；不能据此承诺未来一定提醒。
6. **个性化节奏还不是学习系统。** 已有显式目标和反馈协议，尚未学习用户长期的回复长度、主动性与安慰方式偏好，也未评测重逢、日常仪式、共同成长等完整产品体验。
7. **策略与容量仍待验证。** 配置集中不等于校准；100M、静态加密、跨备份彻底删除等旧阻断没有被这一版解除。

## 下一轮集中验收清单（尚未执行）

- 完整既有回归与 v1—v6 迁移，不拆成小修改反复测试。
- 用户体验链路：倾诉不追问、同关键词错认纠正、原文纠错影响派生记忆、停止引用后的恢复。
- 连续性：回访未发不计数、已问等待、用户已回答不再追问、重复回执不重复记账。
- 编排：单消息合并、补充拍释放、用户打断、旧 trigger 晚完成、非归档输入取消、跨会话影响范围。
- 检索：只用 key 找原文、同向量空间匹配、episode 去重与多原话历史保留。
- 回忆问题不能用当前 trigger 自证；重复消息投递不能取消正在回应该消息的计划；计划保留配置与 bundle 身份。
- 成本分账：检索与计划生成的本地时间、最终模型输入 token、额外确认次数；不只看单项 Recall。
- API/CLI、导出、类型、格式、打包和整版 smoke。
