# 对话传递与计算修复复测记录

2026-09-25。本轮修复了对话输入结构、旧工具记录的位置、自定义风格的传入方式，以及预算计算支持。最终的 8 轮数值专项中，已知金额、价格更正、百分比、追加购票和预算去重均答对。男友聊天自然度仍未全部达标，不能把功能测试通过当作人物体验通过。

## 实际修改

- `context/composer.py` 把当前话语和已过滤的历史传成原生 user/assistant 轮次。记忆、关系、引用主体与虚构标注仍是用户级背景数据，没有提升为系统命令；原有作用域、同意、删除和证据筛选继续生效。
- `romance.py` 完整保留自定义提示词的换行和示例，在默认人物设定之后注入选定风格。设置里的提示词文本没有被替换，示例仍不算真实经历。
- `automation/loop.py` 将历史工具回执放在对话之前。最新用户消息不再被旧工具参数挤到前面；回归测试在修改前能复现这个错误。
- 新增 `automation/calculator.py`，用 Decimal 计算命名算式，支持中英文名称、加减乘除、括号和 `round` 四舍五入。AST 只解释白名单语法，不执行 Python、读文件或联网。限制表达式长度、数量、节点、深度和数值范围；舍入结果标为近似。
- 预算规则区分总花费、余额、方案差额与新增资金。同一笔节省只能计入一次，未选方案的差额不能再次变成追加消费的资金。
- 没有固定回复字数、问题配额、永久倾听模式或删改模型回复的后处理。详细分析仍可按用户要求展开。

计算器通常增加一次模型往返，仍受现有工具循环的次数、时间和 token 预算限制。计算器保证输入算式的求值；模型如何解释预算和现实信息，仍需要单独检验。

## 以成年女性角色“小雨”的角度评审

评审是一个虚构成年女性伴侣的视角，不代表所有女性。

评审口径更正（2026-09-25）：用户明确要求保留个性和正常冲突。以下为当时的体验记录，
不能把反问、解释立场、有分歧或没有立即让步本身视为缺点。只在具体对话中确有重复派题、
忽略回应、无缘由翻转或无依据断言时指出问题。后续按
[个性与关系冲突的评审标准](CHAT_QUALITY_TESTING.md#个性与关系冲突的人工评审)判断，
不以温柔、短句或每轮和解作为男友感的必要条件。

我会感到它愿意关心我，也愿意提出自己的偏好；在独处、朋友聚会和结束聊天时，大体能尊重我的选择。已有明确分歧时，它通常愿意商量，也能承认伤人的表达。引用小说里的控制性台词，没有变成对我的报备要求。

但稳定的自然男友感仍未达到：商量容易变成一段原则说明，提出自己的选择后又把决定全部交回来；双方已经达成安排后，有时继续布置选择题；分析关系时会把可能的动机说得过于确定。道歉也偶尔花很多话解释自己怎样道歉。自定义风格的传递修好了，并不等于模型的所有表达问题都已消失。

因此人物体验判为 **部分符合，未全通过**。没有因回复更短、问号更少或模型自称自然，就给通过分。
