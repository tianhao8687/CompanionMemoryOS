## 本地构建方式与保留证据

使用 Flutter 3.47.5、Gradle 9.3.1、AGP 9.1.0、JDK 21 和 Chaquopy 17。
从既有 Actions 产物只读获取固定版本的三个 ARM64 Python wheel，验证架构和对齐，
没有执行新的 GitHub 构建。

SDK 管理工具在本机出现参数拆分和退出异常。此次构建副本使用已校验、编译配方未变的
FTS5 SQLite 库，并保留预编译原生输入；本地 Flutter 工具仅针对该明确选项跳过自动
NDK 下载，不伪造已安装 NDK。构建结束已恢复 Flutter 工具源码，项目原构建配方未修改。

Flutter 原始运行库含大量调试符号。对旧包中同版本已去除调试符号的库，逐段比较全部
PT_LOAD 和 PT_NOTE 的描述及内容；仅规范化 ELF 头中的节表位置/计数字段，执行代码、
数据和注记完全相同。使用该库通过正常 Gradle 流程重新封装、签名，并重新核验全部
原生库及引擎内容，将 APK 从约 204 MB 减小至约 51 MB。

首次 NDK 下载失败日志、PowerShell 将 Java 标准错误提示误当失败的日志、对应实际
成功的 Gradle 日志和最终通过日志均保留。最终调用改用子进程的实际退出码，未跳过
发布检查。工具改动、原生缓存来源及逐段一致性检查回执都在本地证据目录中。
