# 中文记忆召回优化与复测

测试日期：2026-09-29。所有数据均为独立合成数据库；未访问日常聊天库，未调用远程模型，未上传 GitHub。

## 结论

- 修复了中文助手历史回复漏召回：既可以通过当时的用户问题补齐回复，也可以直接检索助手说过的内容。
- 原 21 题中文回归中，BGE 证据召回率由 76.19% 升至 100%，但它是已查看的小样本，不能代表真实回答正确率。
- 新增 PerLTQA 中文留出集 585 题，BGE 的文档证据召回率为 88.72%，FTS 为 96.24%，本地哈希为 96.41%；本次优化没有改变这组的质量结果。
- 留出集第一条结果命中率仅 40.85% 至 46.32%。目前是“多取几条通常能找到，第一条排序仍一般”，不是整体准确率已经很高。
- 5,000 条规模测试中，BGE 总检索 P95 从 390.70 ms 降至 202.64 ms，约下降 48.1%。不含大模型生成时间。

## 改动范围

`companion_agent/recall_completion.py` 与 `cognition.py`：

- 识别明确询问助手先前发言的中文表达，区分“你向我推荐过”和“我向你推荐过”。
- 允许直接命中的历史助手回复，不再强制要求源问题必须是写作或计算任务。
- 按请求的证据额度返回多条旧回复，去重并保留 assistant 角色和原始回复链，不转成用户事实。
- 保持来源依赖、遗忘、禁止引用、敏感信息、作用域和时间过滤，以及现有上下文预算。

`companion_memoryos/semantic_index.py`：复用每次查询的向量范数，用 Python 3.12 的 `math.sumprod`
代替逐维 Python 循环。仍使用原 SQLite 精确扫描，未增加新数据库、向量缓存或近似索引。
90 组随机向量数值对照通过，覆盖 2/256/512 维；留出集 1,755 次查询的排序 ID 列表前后完全一致。

## 中文对话回归

来源为 [MemoryBank-SiliconFriend 的中文评测数据](https://github.com/zhongwanjun/MemoryBank-SiliconFriend/tree/cf61c4196e4cfdb0f2b7a0316249fa40312dc3a9/eval_data/cn)。
沿用此前固定的 3 人、272 条原始消息、21 道原题与证据标签。保留 user/assistant 角色、真实回复关联及每天的会话边界。
证据标签由 Codex 阅读源对话后整理，并非官方逐轮标注或独立人工盲评。该集合已用于修复，属于开发回归。

| 配置 | 召回 R@6：前 → 后 | 首条命中 P@1：前 → 后 | 优化后 P50 / P95 |
| --- | ---: | ---: | ---: |
| FTS | 71.43% → 95.24% | 47.62% → 66.67% | 16.23 / 25.29 ms |
| 本地哈希向量 | 54.76% → 78.57% | 42.86% → 61.90% | 18.30 / 21.91 ms |
| 本地 BGE 中文向量 | 76.19% → 100% | 42.86% → 61.90% | 26.75 / 32.43 ms |

5 道需要助手旧回复的题，三种配置均从全部漏召回变为证据齐全。用户原话的召回率未下降。
FTS 仍漏掉一道按日期追问过去烦恼的题；哈希模式仍有 4 道完全未命中、1 道部分命中。
最终三种配置均无执行异常。不要把小样本的 21/21 解读为系统在任意中文问题上都能答对。

## 新中文留出集

采用作者公开的 [PerLTQA](https://github.com/Elvin-Yiming-Du/PerLTQA)，参见 [原论文](https://aclanthology.org/2024.sighan-1.18/)。
这是虚构人物的原生中文个人记忆数据，包含事件、对话及官方 `Reference Memory` 证据 ID。
固定版本为 `8d9e19868e239740ef701e603ec205cd581f221b`，不随上游后续变动漂移。
作者标注 CC BY-NC 4.0、非商业研究用途；本次仅用于本地测试，不将数据随产品分发。

- 先排除适配时查看的 2 个人物，剩余 30 人按人物隔离，共 1,639 份原始文档，每人 12 至 76 份。
- 在改生产代码前冻结选题：每人事件/对话各最多 10 题，按种子 `20260929` 与题目 ID 的 SHA256 排序选取。
- 可用事件/对话题共 6,954 道；其中一人只有 3 道事件题、2 道对话题，因此抽取 585 题，而不是补凑到 600 题。
- 本次没有无法解析证据 ID 的排除项。题目及答案、证据标签、memory anchors 均不进入检索索引。
- 先跑旧代码并封存结果；生产修复和开发回归完成后才打开留出成绩，没有针对留出失败调参。
- 前后选题、原始数据哈希、配置一致，分别执行 585 × 3 = 1,755 次查询，无调用失败。

| 配置 | 文档证据 R@6 / Hit@6 | 首条命中 P@1 | P95：前 → 后 |
| --- | ---: | ---: | ---: |
| FTS | 96.24% | 46.15% | 30.18 → 29.92 ms |
| 本地哈希向量 | 96.41% | 46.32% | 32.86 → 32.68 ms |
| 本地 BGE 中文向量 | 88.72% | 40.85% | 42.69 → 39.90 ms |

质量指标及全部排序 ID 前后相同。BGE 的事件题 R@6 为 93.52%，对话文档题为 83.90%。
这次修复针对原生 user/assistant 回复链；PerLTQA 以完整源文档导入，主要用于检查通用检索有无回归。

### 测量边界

每份源文档作为一条用户提供的存档材料导入，整段对话仍保留原说话人文字，但不是逐句原生聊天记录。
使用官方文档级证据 ID，找到文档不代表其中所有答案细节均已进入最终提示。不可与上述逐条原话召回混算。

经过应用实际候选选择、来源过滤与 6 条 / 2,500 token / 12,000 字符预算后才评分。
FTS、哈希、BGE 分别有 527、475、295 题触及上下文预算，部分返回不足 6 条。
文档级命中率不检查完整答案是否保留，不能拿它代替问答正确率。这里的 P@6 按固定 6 作分母，
多数题只有 1 份指定证据，不能把约 15% 的 P@6 解读成只有 15% 的问题答对。

文档保留源日期文本，入库时间统一为合成的 2024-01-01 UTC，查询时间为入库后一天；不验证真实时间推理。
BGE 使用现有本地 CPU 缓存，输入最长 512 token，长文档会截断。没有运行自动记忆提取与最终答案生成，
也不是官方 PerLTQA 问答成绩。FTS 在这组中文长文档上优于 BGE，因此没有自动替换用户的向量后端。

## 速度对照

沿用此前完全相同的规模脚本、30 个固定查询、100/1,000/5,000 条数据规模。
扩容方式是重复公开 LoCoMo 英文原话，仅用于速度对照，不是新增中文质量题或真实多年历史。
共 270 次查询；向量随重复文档复用，但每次查询编码、SQLite 检索、上下文整理均计时。

| 配置 | 条数 | P95：前 → 后 |
| --- | ---: | ---: |
| FTS | 5,000 | 79.23 → 81.01 ms |
| 哈希 | 1,000 | 71.64 → 53.69 ms |
| 哈希 | 5,000 | 242.75 → 147.56 ms |
| BGE | 1,000 | 115.64 → 68.02 ms |
| BGE | 5,000 | 390.70 → 202.64 ms |

FTS 未加速，约 2 ms 的波动不作改善解释。收益来自向量计算，不是放宽检索范围或减少证据。
同机单客户端顺序测试，未与全量 pytest 同时跑速度测试；仍有操作系统及后台负载波动。
这是单次暖机检索测量，不是冷启动、并发压测或完整聊天响应时间。

## 复现

原始公共数据仅保存在被 Git 忽略的 `.agent-tests/recall-benchmark-sources`，脚本按固定 SHA256 校验。
新增可复用入口：

```powershell
.\.venv\Scripts\python.exe -m companion_agent.testing.chinese_retrieval_benchmark --source-dir .agent-tests/recall-benchmark-sources --split holdout --label repeat --runtime-dir .agent-data/embeddings/runtime
```

默认三种配置均跑，最多 1,200 秒，每个向量模式 2,224 个本地输入，远程模型调用 0、自动重试 0。
`protocol.json` 保存完整选题、数据/代码指纹和配置；`queries.jsonl` 保存逐题失败与命中；`results.json` 汇总结果。
适配器测试覆盖嵌套对话结构、官方证据解析、排除项、按人物留出及答案不进入索引。

原始整体评测及限制参见 [此前的记忆召回基线](MEMORY_RETRIEVAL_BENCHMARK.md)。
