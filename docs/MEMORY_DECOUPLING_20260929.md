## 本轮修改

1. **指代与检索分离**：删除 recall_focus.BACK_REFERENCE 的句首词表。
   查询扩展只接受明确的回复关系，或已经通过核心校验且仍有效的事件连续性关系。
   同时重新检查用户、会话、现实层、时间、来源状态和引用限制。
   没有结构化关联时保留原始检索查询；最近对话仍按原有权限与预算进入聊天上下文，
   不强行把上一句认定为当前指代对象，也不将历史原文提升为系统规则。
2. **索引实现与业务分离**：回填、候选搜索、段落读取及删除统一使用
   MemoryStore.semantic_index。PassageSemanticIndex 是可选能力；没有该能力的
   适配器使用整条记录索引，证据窗口仍可按原文词面选取，不会偷偷写入另一套 SQLite 索引。
   修复空的、布尔值为假的自定义适配器被默认实现覆盖的问题。
3. **缓存不再探查索引内部表**：可选 CacheableSemanticIndex 提供实际驻留 ID 和
   后端实例命名空间。完成回执包含后端命名空间、索引模式及来源版本；
   换后端或向量被移除时不能仅凭旧回执跳过重建。
   不提供缓存能力的适配器不复用持久化完成回执。
4. **读写锁分离**：段落向量 SELECT 使用普通读连接，写入的来源版本校验与发布保留原子事务。
   编码仍在事务外进行。SQLite 原始记录、证据及版本链继续作为事实来源。
5. **后台调度与诊断分离**：通用队列接收显式上下文工厂，不再探测诊断器隐藏方法。
   ForkableDiagnosticSink 声明可选的请求快照能力。普通诊断器保留在后台上下文中，
   不再因缺少快照方法而关闭索引维护；其调用守卫也不会被丢弃。
   测试控制器仍绑定原始 trace、失效代次及持久化调用预算。
6. **测试预期与实现分离**：修正此前由生产常量或同一分段函数生成的预期值，
   不再把固定诊断标志当作行为证明。新增检查使用原文、独立长度约束、连续偏移、
   实际适配器调用、传给检索器的查询和传输体是否执行作为证据。

本轮没有改写其他语言规则，也没有宣称整个项目完全不存在耦合。
语义指代能力仍取决于可用的结构化理解和主聊天模型；取消词表不等于解决所有中文理解。
持久化、权限和来源校验是有意保留的依赖，不是需要绕过的耦合。
