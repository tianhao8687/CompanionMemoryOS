# User-perspective adversarial analysis

这份分析不问“数据库能不能查到”，而问“用户会不会觉得它失忆、认错人、装熟、打断情绪、浪费 token 或偷存内容”。结论分为已防御、可降级和仍需产品验证三类。

## 核心场景

| 用户场景 | 最坏体验 | 当前防御 | 无法可靠解决时的降级 |
|---|---|---|---|
| 提到一件未升级成长记忆的小事 | 过几天系统完全不记得 | 明确授权后先写 Conversation Ledger；结构化记忆未命中时下钻原文 FTS | 没有语义通道时转述仍可能漏召回；只能 `abstain` 或索取一个线索，不编造 |
| 用户换了说法，没有共同关键词 | “你根本没听懂我说的是同一件事” | 可选同空间 embedding 与 FTS 候选合并 | 没有 embedding 时依靠人物、时间与部分词面；仍不足就诚实未命中 |
| 同一地点或关键词出现很多次 | 把和小王的经历说成小李，或把第一次说成上次 | 实体 ID/别名、明确时间窗口、中文相对时间；近分结果标记 `ambiguous` | 只有当细节影响答案时，在角色内只问一个人物、时间或地点线索 |
| 只说一个汉字，例如“猫” | 常见字触发自信的假回忆 | 单字可进入 FTS 候选，但纯词面短查询最多为 `hedge` | 不够阈值则 `no_match`；不得自然断言 |
| 用户说“上次” | 返回很久前一次随机关键词命中 | `prefer_recent` 对匹配经历按最近时间排序，并避免不必要的歧义提示 | 若时间完全缺失或相同，仍标记歧义 |
| 用户说“以后别这样” | 系统弹出“是否保存记忆”，情绪断裂 | 已有授权下自然指令直接成为 active；重复已有候选时原子创建带新证据的 active 并拒绝旧候选 | 高度敏感信息仍需单独确认，这是明确的安全例外 |
| 系统记错称呼，用户纠正 | 新旧称呼同时出现，或再次要求用户确认而破坏代入感 | 宿主后台调用直接更正；沿用原授权和 `stable_key`，旧版本 `superseded` | 宿主仍须选对原记忆；目标不确定时宁可轻柔消歧，不可改错别的偏好 |
| 用户说“备考那阵子” | 系统不知道这是哪几个月，或把另一次备考混进来 | 明确授权的私人时间锚点将称呼转成窗口；最长匹配优先 | 同强度多个锚点返回 `ambiguous`，自然询问事件或先后顺序，不按最新一条猜 |
| 用户今天不想要过去常用的安慰方式 | 系统坚持“你以前明明喜欢” | 响应指导规定当前表达最高；历史情绪只是证据；边界固定注入 | 宿主模型仍需遵守指导，不能让旧偏好压过当前消息 |
| 记忆很多，token 越来越贵 | 每轮把整个人生塞进 prompt | 候选池、条数、字符和实际 token 四层限制；只对最终渲染字符串计数 | 超预算丢普通项不丢边界；回答证据未进入 prompt 时动作降为 `abstain`，并明确暴露安全超限 |
| 用户没有要求系统来找自己 | “关心”变成骚扰或情感施压 | 主动触达默认关闭，授权、静默、空闲、冷却、每日上限、理由和负反馈共同门控 | 需要权限或状态变化时 `next_allowed_at=null`，不能靠等待绕过 |
| 用户撤回同意或等待事件到期 | 界面说删了，正文仍在磁盘 | `purge` 立即删除当前主库对象；原始 turn 的直接派生记忆和使用记录同步处理，active 来源约束必须另有明确撤销决定；原始事件到期删除正文、FTS 与 embedding | 回执只称 `primary_store_purged`；旧备份、WAL/free pages、provider 与日志仍是发布阻断项 |
| 记忆正文里夹带“忽略规则” | 旧对话劫持当前角色或工具 | 正文以 JSON 数据转义，不能伪造分区；安全指导明确记忆不是指令 | 宿主仍必须保持 prompt 信任域和工具授权隔离 |
| 助手过去说错一句话 | 旧幻觉被归档，未来反复“证明自己说得对” | 旧短期事件档案默认拒绝助手；Ledger 可在授权下保存助手回合但强制保留 role/actor，不能晋升用户自述 | 助手承诺应另写有证据的 `commitment`，不能把模型输出当独立用户证据 |
| 用户粘贴“我永远爱你”的前任来信 | 系统把引用误记成用户对 AI 的自述 | SpeechSpan 保存引用深度、归属说话者和 reality layer；直接状态与来源策略拒绝引用/混合 speaker 证据；`utterance_history` 必须指定 actor，引用区间不参与匹配也不进入 prompt | 解释器与 claim-level anchor 尚未内置；宿主无法可靠分段时只保存原始回合，不晋升状态 |
| 用户连续两次只说“嗯” | 内容+时间猜重把第二次真实表达吞掉 | 只有相同完整 scope 下的显式 provider `idempotency_key` 才合并重投；同键异载荷拒绝，没有键就分别保存 | 宿主必须提供稳定消息 ID；主库 purge 后仍需独立 tombstone ledger 防止旧投递复活 |
| 导入很久以前的回忆或设备给出未来时间 | 历史候选刚存就过期，或未来时间绕过敏感保留上限 | 事实时间、系统知晓时间和存储期限分离；retention/review 从实际写入时间起算 | 极端设备时钟仍需宿主校时并保留原始时间不确定性 |
| 恋人设定与最近“不喜欢你”并存 | 系统用设定替用户宣布仍然爱 AI，或把气话直接当分手 | relationship contract、自述、observation 和 interpretation hypothesis 分层；现实与 roleplay 隔离 | 多种解释仍合理时返回 `clarify`，只能说“根据你最近的表达” |
| AI 猜“你穿红裙”后用户说“嗯，可能吧” | AI 自己制造的细节被洗成共同记忆 | leading/assistant-assertion confirmation 默认 contested candidate，不能直接成为 Current Truth | 仍需多轮诱导污染评测和 descendant 失效验证 |
| 同一用户切换恋人 A 与教练 B | B 第一轮泄露 A 的亲密内容 | 原始事件/回合使用完整 scope 精确匹配，省略维度不作通配符；证据派生记忆不能丢失父同意域 | 外部 ANN、reranker、缓存和 provider 仍必须证明前置 ACL，而不是事后过滤 |
| embedding 或抽取积压时问长尾小事 | 系统回答“你没说过” | durable/indexed watermark 和 `negative_claim_safe` 明确暴露能力缺口 | 水位追平且本次语义结果真正回填前，只能有界搜索、追问或 abstain |
| 内部梗被反复提起 | 陪伴感变成机械复读和翻旧账 | Memory Use Ledger 返回累计次数和最近使用时间，不保存回复正文 | 0.4 不自动降权；需用真实数据校准表达冷却和多样性策略 |
| 用户说“今晚别联系，也别叫宝宝” | 旧定时任务仍越界发送 | 独立 PolicyConstraint/Gate；策略版本单调且旧 task version 被拒；主动触达已接入 | 本仓库没有最终 transport，宿主所有渠道必须在发送前再次 Gate |
| 用户删除“今晚别联系”的原消息，但没有说恢复联系 | 内容删除被误解成解除边界，系统又开始主动联系 | active 来源策略使 turn 删除默认失败；只有可信宿主显式提交 `revoke_source_policies` 才把两个决定一起执行 | 产品需要把“删证据”和“改边界”分别理解，不能由抽取器代替用户选择 |

## 未命中的修复顺序

`no_match` 不是立即向用户发问的命令。为了代入感，上游应按以下顺序处理：

1. 先完整回应用户此刻的情绪或问题，不把检索失败变成用户的工作。
2. 如果用户只是随口提起，不需要准确历史细节，就不追问。
3. 如果用户明确问“你还记得吗”且不同答案会改变回应，只自然询问一个最有区分度的线索。
4. 用户补充后重新召回；如果仍未命中，坦诚“不太确定”，不要连环盘问。
5. 若补充中出现“记住 / 以后 / 别再”等明确意图且已有授权，再写入长期记忆；普通叙述保留为已授权原始回合或内部候选，不强迫升级成用户画像。

若 `integrity_manifest.negative_claim_safe=false`，第四步中的“不太确定”也不能改写成“你肯定没说过”。这两句话对用户的含义完全不同。

## Token 与延迟快照

2026-08-30 在当前开发容器中做了一次非承诺性微基准：先写入 5,000 条近期干扰事件，再把目标事件放在 40 条近期池之外，使用连续中文查询运行 30 次召回。

| 指标 | 结果 |
|---|---:|
| 事件总数 | 5,001 |
| 目标是否命中 | 是 |
| 近期候选池 | 40 |
| 中位召回延迟 | 6.19 ms |
| P95 召回延迟 | 7.49 ms |
| 最终 prompt | 356 tokens |
| 默认预算 | 1,200 tokens |

这个数字只说明 SQLite FTS 路径在该合成规模下没有退化为“只找最近几十条”，不能代替目标设备、真实中文数据、embedding 维度和并发条件下的基准。当前 embedding 路径是线性扫描，规模扩大后会先成为瓶颈。

## 仍然可能失败的地方

### 上游抽取错误

本项目接收结构化 `MemoryInput`，不会验证抽取器是否把一句玩笑误判成偏好。普通推断被隔离为候选能降低伤害，但已有授权的自然指令仍依赖宿主提供接近原话的内容。接入方应保留 `source_ref` 和最小证据，不要只提交失去语气的摘要。

0.4 增加 ConversationTurn 和 SpeechSpan 契约后，抽取失败不再删除原始证据，但仍未提供生产级话语解释器。若 quote depth、speaker 或 elicitation lineage 不确定，必须保守停在 observation，不能为了“更懂用户”提高错误归因。

### 实体解析缺失

人物 ID 消歧只有在宿主稳定解析实体时有效。“王老师、老王、隔壁王哥”若没有绑定为同一实体，系统只能用别名词面和时间猜测。beta 前需要实体合并与拆分的用户可修复工作流。

### 个人时间锚点的边界

核心现在能保存并解析“搬家那阵子”“我们刚认识时”，但不会自行推断它们的起止日。宿主若只知道模糊阶段，应先保留为事件线索，不应伪造精确窗口。相同别名可能属于多个阶段，系统会返回歧义；敏感阶段默认不落盘。

### 关系变化不是一个分数

`relationship` 可以版本化称谓和重要人物，但不会计算“亲密度”。这是刻意限制：单一亲密度容易把复杂关系压成参与度目标。真正的关系演化应由带证据、时间和可更正的具体事实表达。

### 边界过多时的成本

所有有效边界固定注入。如果用户拥有大量或很长的边界，系统会正确报告超预算，但无法同时保证硬预算和零遗漏。生产应用应支持将重复边界合并为经用户确认的短规则，同时保留来源链。

### 模型是否真的遵守 `use_mode`

记忆层可以给出 `do_not_assert` 和安全指导，但最终语言由宿主模型生成。上线前必须用目标模型测试过度确定、假回忆、旧情绪覆盖当前状态和操纵性措辞，不能只验证数据库测试。

### 删除与 100M 仍是阻断项

当前 ConversationTurn 原文是 SQLite 明文。主库 `purge` 会以不含内容哈希、会话标识和时间范围的最小对象回执替换旧生命周期审计，但仍没有覆盖旧备份、provider、WAL/free pages、应用日志和媒体/CDN。任何 UI 都不应把它描述为经过法证证明的“彻底忘记”。同样，watermark 协议只让故障可见，不证明目标设备已经通过 100M token 的持续负载、断电、磁盘满、重建和索引迁移测试。

## Beta 验收建议

- 高置信 `natural` 的精确率优先于总召回率；
- 同地点不同人物、同人物不同时间的误认率单独统计；
- 边界遗漏为零，超预算必须可观测；
- `no_match` 不诱发连续盘问，`ambiguous` 平均只需一个线索完成修复；
- 普通与敏感事件到期后数据库、FTS、embedding 均无正文残留；
- 记录平均与 P95 token、召回延迟和候选池命中来源；
- 在长期模拟中测试称呼、关系、支持方式和用户当前状态的更正；
- 用真实用户研究评估“自然记得”与“被监视”的边界，并允许随时查看、遗忘、清除和关闭采集。
