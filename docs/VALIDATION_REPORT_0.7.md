原先缺少构建后端的离线尝试失败记录仍成立。用户允许继续获取构建依赖后，以下路径成功：

```bash
uv build --out-dir dist
python -m pip install /absolute/path/companion_memoryos-0.7.4-py3-none-any.whl
python -m pip install /absolute/path/companion_memoryos-0.7.4.tar.gz
```

两个 `pip install` 分别运行在不同的空虚拟环境内。检查了安装后的入口点、包内 `defaults.toml`、拆分后的 `schemas/`、解释/事件/语义模块，以及原始证据链查询。源码包安装过程中 pip 实际重新构建 wheel，并成功安装。

wheel 环境还启动了真实的本地 `serve` 进程，使用临时数据目录和空闲回环端口，通过标准 HTTP 请求检查：健康状态与版本、原始回合存入、解释候选生成及幂等、候选不直接成为当前真值、原文召回、真实词元计数、用户状态查询不混入 AI。`init` 与两个库的完整性检查均通过；测试进程已退出。

本轮没有改动功能代码，因此没有重复运行完整 pytest；199 项和 89% 仍是前一轮整版集中验证结果，不把安装冒烟检查计入 pytest 数量。安装检查脚本曾误用一个不存在的配置路径，改为实际的 `tokenization.encoding` 后完成检查，不涉及产品代码修复。

## 真实使用问题覆盖

- 主体：用户、AI、两个第三人使用同一 predicate，甚至同一 stable key，也不串查询或状态覆盖；省略主体仍默认当前用户，用户画像不混入其他主体。
- 自述：明确记住用户偏好与第三方/AI 偏好分开；错误标注为他人 direct self report 的输入不能借此变成用户自述。
- 日期：新加坡午夜后的“今天”、洛杉矶“昨天”、夏令时日界与 UTC 默认行为；实际原文召回窗口也被验证。
- 解释：宿主提交候选，原始正文/哈希/原有 spans 不变；确定性话语规则优先，模型可补 `wrong_reference` 自然变体。中途数据库写入失败会回滚已创建候选和事件，原始回合仍存在。
- 事件：面试、电话、拒绝跨日连接；话题不匹配与宿主声明的时间间隔检查；显式重新归属、合并、拆分和旧归属冲突。
- 连续性：AI 通过同一主体状态接口表达；静默影响只在宿主提交真实使用回执时记账，不保留输出正文/哈希、不自动降低权重；重复回执不重复计数。
- 接口替换：自定义 TokenCounter 参与实际上下文预算；SemanticIndex 写入、查询、删除适配验证，默认仍使用本地 SQLite。

## 20 场景聊天回放

`tests/fixtures/conversation_replays_0_7.json` 包含人工编写的中文场景；每个场景 16 条用户消息，配 16 条合成助手消息，共 32 条 ConversationTurn，合计 640 条消息。

场景覆盖关系设定、同名/多人物、偏好更新、称呼变化、气话后澄清、角色扮演、面试进展、宠物别名、AI 状态、同关键词杯子、取消计划、倾听需求、离职、临时饮食、考试、用户纠错、错误前提、首次话题、长间隔回忆和未被抽取的小事。

最终检查并非只看候选命中：检查进入上下文的目标原话、说话者、证据来源、词元预算，以及无证据状态不被编成确定事实。未抽取小事场景保留原文并验证词法可召回路径，不把它解释成任意语义转述都能找回。

限制：模型输出为固定测试数据，没有实际 LLM 抽取、生成或人工评阅最终聊天回答。因此本轮证明的是证据交付和候选处理协议，不是模型理解率、长期代入感或真实端到端回答质量。

## 发现与修复

集中阶段发现并修正了模块拆分后的导入/类型问题、格式问题，以及一个新时区测试缺少必填 `utterance_actor_id` 的用例构造错误。最后完整运行是上述 199 项全部通过的结果；中断或失败的早期运行不计作通过。
