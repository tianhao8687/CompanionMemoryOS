# 网易云点歌闪现根因

日期：2026-10-16。状态：根因已确认，零闪现修复尚未通过，不发布实验候选版本。
日常安装仍为心隅 0.2.24+27；没有替换快捷方式、更新 GitHub 或改动 Android。

## 已确认的两处窗口显示逻辑

本机网易云 3.1.41.205529，`cloudmusic.dll` SHA-256：
`7f667f876caf94bc3dac3b0070d3e495117005fafdcf18b6aaa51eb004edac8c`。

只读检查安装文件，未修改网易云文件、注入进程或开启调试端口。

1. 启动转发函数（RVA `2df090`）把 `--webcmd` 转成 IPC 3，随后还会发 IPC 1。
   IPC 1 对应 `foregroundpreinstance`，用于显示已有窗口。
2. 更关键的是，客户端自己的前端同样会显示窗口。安装包 `orpheus.ntpk` 中
   `pub/hybrid/73.chunk.c6406e5.js` 的 `ipcMessage` 订阅在收到 `webmessage`
   时发送 `app/activeWindow`，参数 `from: webmsg`。
   `pub/hybrid/app.chunk.c6406e5.js` 的 `activeWindow` 处理器在此来源下无条件
   派发 `showWindow`。因此仅省掉 IPC 1 仍然无法避免显示主窗口。

`SW_HIDE` 只影响启动时的窗口显示提示。现有 20 毫秒隐藏轮询、焦点锁和临时置顶
均在外部工作，不能取消播放器内部的 `showWindow`。窗口可能先进入显示状态，再被隐藏。
前台焦点没有变化也不代表窗口没有显示。

## 唯一一次实际点歌验证

实验候选使用单独构建的引擎和原生界面、全新合成心隅数据。通过真实 HTTP
`/api/music/pick`、ToolHub、内置 MCP 契约，直接向精确匹配的网易云消息窗口发送
IPC 3。没有额外启动转发进程，没有发送 IPC 1，也没有开启隐藏或焦点保护。

只对当时已选中的同一首歌发送了一次播放请求；没有切换成其他歌曲，没有重启网易云，

## 后续实施边界

彻底消除点歌闪现需要绕过触发 `activeWindow` 的外部命令路径，直接操作播放器的
播放队列。客户端内部控制通道是待验证的替代方向；目前没有证明它在本机版本下可用。
不能把这一方向描述为已经实现，也不能承诺所有网易云版本都支持。

不得用更短轮询、反复夺回焦点、缩小窗口、透明窗口或最小化替代零闪现的验收。
下一次候选需要同时证明真实点歌成功、播放进度增长，以及从请求前到延迟窗口期结束
都没有网易云主窗口显示或取得前台事件。必须保留失败，不为测试反复切换不同歌曲。
