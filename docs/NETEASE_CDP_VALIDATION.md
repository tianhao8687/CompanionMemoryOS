# Windows 网易云后台点歌：最小验证与执行层改动

日期：2026-10-16。范围仅为 Windows 音乐 MCP 执行层；未重构 Agent、修改 Android
播放路径或替换桌面安装版。用户当前安装的心隅仍为 **0.2.24+27**。

以上为验证当日状态；当前 Windows 发布版本及附件见 [0.2.26 交付说明](XINYU_0226_DELIVERY.md)。

## 结论与适用范围

本机网易云 **3.1.41.205529** 的当前运行时支持这条路线。在已登录、控制通道已经初始化的
前提下，原生队列操作能后台点歌，不必经过系统协议或激活窗口。最小化和托盘状态均通过
持续输入验收。已增加 WinGet 当前列出的最近四个 Windows x64 构建的执行层适配，
见下表；其中三个旧构建只有官方包审阅和离线契约验证，尚未逐版实机验收。

控制口固定为 `127.0.0.1:9223`；实机检查未出现非回环监听。连接前后核对端口 PID、
进程完整路径、客户端版本、唯一主页面和已审阅函数的 SHA-256。任何检查失败均停止。
只向模型暴露原有固定音乐工具，CDP 与 JavaScript 执行器是私有实现，不接受模型脚本、
任意 URL、端口、窗口、进程或本地路径参数。

## 原点歌链路与变化

| 操作 | 原实现 | 本次实现 |
| --- | --- | --- |
| 搜索 | 固定网易云 HTTPS 接口 | 保留，无窗口操作 |
| 点歌 | `cloudmusic.exe --webcmd=orpheus://…`，外围窗口保护 | 已移除；只连接已运行客户端的本机 CDP，操作内部队列及播放 |
| 暂停、继续、下一首、上一首 | 精确匹配 `cloudmusic.exe` 的 Windows GSMTC 会话 | 保留；不发送全局媒体按键 |
| 播放状态 | GSMTC，必要时读取本机进度 | 可用时使用原生 CDP 歌曲 ID / 进度；控制能力仍来自定向 GSMTC |
| 单独打开客户端 | 独立启动工具 | 仍独立；点歌函数不会调用它，也不会因通道失败而启动或重启 |

旧协议转发链会进入客户端显示/激活窗口的逻辑；先显示再隐藏、恢复原窗口的补丁无法满足
零闪现要求，详见 [原窗口闪现根因](NETEASE_WINDOW_FLASH_ROOT_CAUSE.md)。新点歌路径不含
`Popen`、`os.startfile`、`ShellExecute`、窗口激活、模拟点击或键盘输入。
源码中的 `orpheus://orpheus/pub/app.html` 仅用于识别 CDP 主页面，绝不交给系统打开。

参考了 [cloudmusic-desktop-mcp](https://github.com/Seraph310/cloudmusic-desktop-mcp)
的内部队列思路。没有照搬其协议点歌或全局媒体键控制。该项目采用 MIT 许可，作者
Seraph310；本实现另加了本地所有权检查、接口指纹、队列保护及真实进度确认。

## 必须单独适配的细节

1. 当前运行时的 store 在模块 8，格式化器在模块 213；参考实现及安装包里的静态模块编号
   不完全适用。现在从已加载导出中唯一识别 store、格式化器、队列转换器及原生播放器，
   不执行未加载模块。客户端会热更新网页资源，因此只检查 EXE 版本不足以保证兼容。
2. 普通 `addItemToCurPlayingList` 会重排原队列的随机顺序。实测发现后弃用：现在保留原有
   对象，仅追加新条目，并通过官方 `replaceCurPlayingList` 持久化/同步。没有清空队列；
   新条目的显示序号和随机序号分别取已有最大值加一。已有歌曲只选择，不追加或移动。
3. 同一首歌已经暂停时，再调 `playOneTrackInPlayingList` 可能出现状态显示 playing、
   实际进度不动。此情况改走固定 `playing/resume`，并仍等待真实进度推进。
4. 暂停状态事件与最后一个进度回调不完全同时到达，实测最后一帧约有 320 ms 的补报。
   验收在有界时间内等待稳定暂停区间，而不是把第一帧暂停标签当作声音已经停止。

点歌前后检查歌曲 ID、显示顺序、随机顺序和播放模式。并发改队列、队列满、重复资源或
特殊电台模式返回错误；不会为了完成点歌而覆盖用户的新操作。当前仅接受普通 track
资源。首版按 fee 0 / 8 放行的限制已移除，`silent_rights_unverified` 不再用于拦截收费歌。
fee / status 是资源标签，不能代替账号实际权限。所有收费类型都交给客户端原有
`checkPlayPrivilege → setPlaying → nativePlay` 路径处理，保留客户端提供的合法试听。
不更改权限字段、获取绕过限制的音源、自动购买或改用协议/窗口播放。

从原生播放实例读取 `resourceIsTryType` / `resourceIsFullTryType`，对外只返回
`playback_access=full | preview | full_trial | unknown`。片段试听可附带毫秒起止范围；
不会输出 Cookie、账号会员配置、流媒体 URL 或完整内部权限对象。必须同时匹配实际
资源 ID、playId 和已加载状态，旧曲目的进度/权限不能套到新曲目上。`unknown` 不宣传
完整播放。工具说明也已更新，旧 Windows 目录会重新发现，保留所有已有权限规则。

成功回执必须同时满足：目标 ID 正确、状态 playing、同一播放实例的原生进度新鲜且实际
增加超过 200 ms、队列/模式一致。单纯命令返回或 playing 标签不足以成功。发送后超时
返回 uncertain，禁止自动重发或切换到协议/GUI 路径。一次连接有总时限，并关闭代理继承。

## 初始化与发布边界

本次已在用户正常退出客户端后带参数启动一次，后续点歌验收没有重启客户端。
初始化/登录可能需要用户进入客户端，属于单独步骤，不承诺首次初始化本身零显示。
没有修改网易云桌面快捷方式、自启动、账号或系统协议注册。

维护人员需在客户端完全退出后单独启动控制通道，例如：

```powershell
Start-Process -FilePath '<已确认的 cloudmusic.exe 完整路径>' `
  -ArgumentList '--remote-debugging-port=9223','--remote-debugging-address=127.0.0.1' `
  -WindowStyle Hidden
```

`Hidden` 只是初始化的启动提示，不是点歌时掩盖窗口的机制。启动后仍必须检查真实监听
地址、客户端身份与接口指纹。客户端若正常退出后由普通快捷方式打开，可能没有控制参数；
此时点歌会明确失败，需要单独重新开启控制会话，绝不会每次点歌自动重启。

这次没有生成新安装包、替换已安装 0.2.24、上传 GitHub 或测试 Android。原生 CDP 路线
已在当前版本验证可用，因此暂不引入 neteasecli / mpv，避免同时改变播放器与账号方案。
