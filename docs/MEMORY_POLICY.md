# Memory policy

## 存储决策表

| 情况 | 结果 |
|---|---|
| 用户拒绝保存 | `discard` |
| 普通信息，未明确要求记住 | `candidate` |
| 普通信息，明确授权且要求记住 | `active` |
| 敏感信息，授权未知或缺少明确请求 | `discard` |
| 敏感信息，明确授权且要求记住 | `active`，期限受敏感上限约束 |
| 高度敏感信息，明确授权且要求记住 | `candidate`，必须再次确认 |
| wellbeing signal | 强制 `ephemeral` |

候选状态不是“低置信度事实”，而是“不可用于个性化的待确认提议”。只有 `active` 参与召回。

## 冲突原则

优先级从高到低：

1. 用户当前消息中的边界、身份和情绪表达。
2. 已确认且仍有效的边界。
3. 已确认的稳定事实和支持策略。
4. 有时间语境的情绪经历与共同经历。
5. 候选或推断信息不得进入响应上下文。

## 禁止优化目标

应用不得利用本项目的记忆能力优化以下行为：

- 制造“只有系统理解用户”的排他感；
- 以离开、沉默、失望或内疚换取互动；
- 鼓励用户减少真实人际支持；
- 把危机、创伤或健康信息用于参与度定向；
- 将历史标签冒充当前诊断或确定身份。

## 删除语义

- `forget`：保留记录和审计，但从有效记忆中移除，适合可追踪撤回。
- `purge`：删除记忆正文和证据；审计只保留 ID、类型、内容哈希和时间。
- `export`：按 `user_id` 导出该用户的全部生命周期状态，不跨用户。
