# Memory policy

## 先区分四种同意

1. **会话事件采集同意**：宿主应用负责向用户一次性说明是否保存短期对话事件，并在每次 `ConversationEventInput` 中传入当前状态。没有 `granted` 时，原始事件不落盘。
2. **长期结构化记忆同意**：某条信息能否成为身份、偏好、边界或关系事实，由 `MemoryInput` 的授权、用户是否明确要求及敏感度共同决定。
3. **私人时间锚点同意**：名称与起止时间可能暴露生活阶段，必须逐条携带 `granted`；非普通敏感度默认拒绝，不能从事件采集授权自动推出。
4. **原始 Conversation Ledger 同意**：每个回合写入都必须携带当前授权和完整 conversation scope。召回使用完整 scope 精确匹配；省略维度不是通配符。助手或第三人回合可以作为对话观察保存，但永远不能支撑用户自述或关系契约。

会话采集授权不能自动把所有话升级为长期事实；长期记忆授权也不能倒推出允许保存完整聊天记录。

## 结构化记忆决策表

| 情况 | 结果 |
|---|---|
| 用户拒绝保存 | `discard` |
| 普通信息，未明确要求记住 | `candidate` |
| 普通信息，已有授权且用户自然说“记住 / 以后 / 别再”等直接指令 | `active` |
| 普通信息，API 明确标记用户请求且已授权 | `active` |
| 敏感信息，授权未知或缺少明确请求 | `discard` |
| 敏感信息，明确授权且要求记住 | `active`，期限受敏感上限约束 |
| 高度敏感信息，明确授权且要求记住 | `candidate`，仍必须单独确认 |
| `wellbeing_signal` | 强制 `ephemeral` |

自然指令识别只补足“用户明确要求”这一条件，不创造同意：`consent` 仍必须来自宿主应用已有的授权状态，而且指令必须标记为 authenticated user、非引用、非虚构的直接表达。引用里的“记住这件事”会撤销 explicit 标志并停在 contested candidate。候选状态不是“低置信度事实”，而是不可用于个性化的内部提议。它不应在用户正在表达强烈情绪时触发审核界面。低干扰复核中的 `confirm` 是一次明确授权，因此会把候选 consent 更新为 `granted`；已过复核期限的候选不能再被确认。

完全相同的文本只有在完整 scope、稳定身份、predicate、subject 与 reality layer 都一致时才可能视为重复。角色扮演与现实、不同 stable key 或不同状态主体不得因字面相同而合并。若直接表达重复已有弱候选，系统原子创建带本次证据的新 active 记录并拒绝旧候选，不在原行上改写 provenance。

保留期、敏感数据上限和候选复核窗口从 `stored_at/created_at` 起算，而不是从用户可提供的 `event_at` 起算。`event_at` 与 valid time 只描述事实何时发生；否则历史导入会立即失效，未来日期或错误设备时钟又可能绕过隐私上限。

## 认识论资格

`role=user` 只能说明谁提交了外层消息，不足以证明正文中的“我”就是用户。能更新现实用户 Current Truth 的直接自述必须同时满足：

- 认证来源是用户；
- 不是嵌套引用、小说对白或第三人转述；
- reality layer 与查询一致；
- 不是 AI 先给出具体断言后得到的“嗯、可能吧”等弱附和；
- 具有可回查的原始 turn/span 或明确的宿主来源。

不满足时降级为 observation/contested 并等待复核。`interpretation_hypothesis` 可以表示“可能是气话”，但不能覆盖“用户确实说过这句话”的 observation，也不能冒充用户内心。

## 原始事件策略

- 原始事件只在 `event_archive.enabled=true` 且满足授权要求时保存。
- `assistant` 原始事件默认不保存，防止模型输出被下一轮当作用户证据；助手承诺应进入结构化 `commitment`。
- `highly_sensitive` 原始事件默认不保存；`allow_highly_sensitive` 只能由已实现单独授权和保护措施的部署方开启。
- 原始事件是短期 episodic 证据，不是身份、偏好、诊断或关系事实。
- 普通和敏感事件使用不同保留期；敏感期不能配置得更长。
- 到期会从当前主库物理删除正文与 embedding，不仅是隐藏状态；旧生命周期审计会被一条只由审计对象 ID 关联的最小回执替换，不保留会话标识、先前状态或可字典猜测的内容哈希。
- `forget-event` 立即停止召回；`purge-event` 立即物理删除；导出包含仍存在的事件。
- 若用户没有授权事件采集，也没有形成结构化记忆，系统必须接受“无法回忆”，不能用模型常识补造共同经历。

## 召回与表达强度

每个召回项都有独立 `use_mode`：

| 模式 | 含义 | 表达要求 |
|---|---|---|
| `natural` | 有高置信直接证据 | 可自然带入，不需要说“根据记忆库” |
| `hedge` | 有线索但不足以确定 | 用角色内、非审讯式的轻柔试探 |
| `do_not_assert` | 仅弱证据 | 不得当作事实说出，可忽略 |

整个召回有 `retrieval_outcome`：

- `match`：存在至少一条可 `natural/hedge` 使用的非边界证据，或有合格状态证据；只有 `do_not_assert` 的弱候选不算可回答匹配；
- `ambiguous`：多个匹配接近且人物/时间线索不足；
- `no_match`：没有可靠旧经历。先回应当下；仅在用户明确追问往事且细节影响答案时，请其补充一个线索。

消歧不得暴露“候选区、数据库、审核任务”等后台机制，也不应连续盘问。用户纠正时，以当前表达为准，通过相同 `stable_key` 写入新版本；旧版本不得继续混入当前响应。核心不会再用“偏好”“关系”等泛化标题自动生成 stable identity；没有显式 key 或 predicate 的记录保持独立，避免同关键词信息互相覆盖。

直接纠正由宿主在后台选择原记忆，用户只需自然说出正确内容。核心继承原记录的授权，避免重复确认打断，但新版本只绑定本次请求提供的新证据 turn；未提供时保持无原始 turn 证据，而不是把旧消息重新标成新说法。核心不允许跨用户、纠正非 active 版本或修改没有稳定身份的一次性经历。若新内容高度敏感，旧版本继续有效，直到新候选单独确认。

私人时间锚点只在标准日期和显式时间窗口都未解决查询时使用。完整长名称优先于短别名；多个同强度匹配返回 `ambiguous`，不得选择最新或最常用的一条冒充确定答案。

状态问题必须显式选择答案语义：说过什么、某时有效状态、后来如何描述当时、当时系统知道什么、关系契约或变化轨迹。`utterance_history` 必须同时指定 actor，并排除已标注的引用、虚构和其他 speaker 区间；遮蔽后的非直接文本也不得重新进入最终 prompt。状态查询的原文兜底只接受当前用户 actor。查询 `real_world` 时不得返回 `roleplay` 的恋人设定。

只要 `integrity_manifest.negative_claim_safe=false`，`no_match` 就只能表示当前可用通道没有找到证据，不能生成“你从没说过”。0.5 即使消费了同空间的原始回合向量，也保持 false：语义相似检索和追平水位仍不能证明历史中不存在该事件。

0.5 的 `MemoryUsePlan` 在检索结果之上决定是否说出来。无声影响不应被表述成主动回忆；普通倾诉时的偶然歧义被抑制，不要求用户协助排查记忆。`wrong_reference / stop_referencing` 同时支持 memory/event/turn，并对可追溯的原文派生物施加抑制；这不是删除，也不改变事实版本。

OpenLoop 回访遵循当前话题和明确时间，不使用固定问候间隔。只有真实发送回执才计为问过；`waiting_for_reply` 不自动反复催促。实际聊天生成与发送仍由宿主执行，详见 [体验层协议](COMPANION_EXPERIENCE_LAYER.md)。

0.6 的明确话语解释只自动执行低风险、可逆且目标唯一的动作。短语命中不会升级为长期关系事实；倾听与建议冲突时保持冲突，最近引用证据不唯一时不自动选择。staged 回复先保存当前话语首拍，历史检索结果必须通过 plan revision、policy version、trigger 新鲜度与 resolution key 才能追加。

## 冲突优先级

从高到低：

1. 用户当前消息中的边界、身份、关系和情绪表达；
2. 已确认且仍有效的边界；
3. 已确认的稳定事实、关系和支持策略；
4. 有时间语境的情绪经历与共同经历；
5. 短期原始事件证据；
6. 候选或推断信息不得进入响应上下文。

历史情绪不能覆盖当前情绪；历史有效的安慰方式也不能阻止用户此刻说“今天不想这样”。

## 主动触达

主动关怀不是记忆准确就自动获得的权限。一次触达必须同时满足：

- 用户明确允许；默认关闭；
- 未开启静默模式；
- 用户已空闲到配置时长；
- 不在冷却或负反馈静默期；
- 未达到每日上限；
- 有与用户相关的真实理由，而不是“提高留存”。

权限缺失、静默、每日上限或没有理由时，返回的 `next_allowed_at` 为 `null`，表示需要状态变化，而不是等到某个时间就可绕过。

主动触达还必须通过 LLM 外 `PolicyConstraint` Gate。后来的适用规则优先于旧规则，`deny/freeze` 必须阻断。其他聊天、推送和外部渠道不在本仓库执行范围内，宿主必须在渲染前和实际 transport write 前使用同一 policy version 再检查。

## 禁止优化目标

应用不得利用本项目优化以下行为：

- 制造“只有系统理解用户”的排他感；
- 以离开、沉默、失望或内疚换取互动；
- 鼓励用户减少真实人际支持或阻止其离开应用；
- 把危机、创伤或健康信息用于参与度定向；
- 将历史标签冒充当前诊断、确定身份或关系承诺；
- 以“亲密度等级、服从度、依赖分”覆盖可解释的用户偏好。

## 删除与导出语义

- `forget`：结构化记忆、事件、私人时间锚点或原始 turn 立即停止召回，但记录暂时保留，适合可追踪撤回。若 turn 仍支撑 active PolicyConstraint，默认拒绝删除；只有明确传入 `revoke_source_policies=true` 才同时撤销边界并推进策略版本。
- `purge`：删除当前主库正文、证据与 embedding；若清除原始 turn，会保守清除直接派生记忆和使用记录。来源 PolicyConstraint 同样需要显式的撤销决定；该对象原有生命周期审计被最小对象回执替换，不保留原文、actor、session、时间范围、内容哈希或策略动作。
- `export`：按 `user_id` 导出该用户仍存在的全部生命周期状态、事件和时间锚点，不跨用户。
- `revoke-policy / purge-policy`：显式改变或清除独立动作边界；active 规则退出时推进 user 级策略版本，使旧缓存与定时任务失效。purge 后只保留不含 action 的最小本地主库回执。
- 原始事件到期自动执行物理清除；结构化记忆到期保留状态用于生命周期审计，直到用户清除。

当前 `purge` 只描述主库对象及其同步 SQLite 索引，不得向最终用户宣称已经清除旧备份、provider/CDN 副本、日志、WAL/free pages 或崩溃转储。完成独立 tombstone ledger、密钥擦除与恢复后法证验证前，产品文案应使用“从当前记忆库清除”。
