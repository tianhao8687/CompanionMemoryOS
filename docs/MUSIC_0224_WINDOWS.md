# 0.2.24 Windows 点歌窗口遮挡修复

版本：0.2.24+27。日期：2026-10-16。

后续用户复测仍会短暂闪现，**0.2.24 不满足“完全不显示网易云窗口”**。
窗口层级和焦点保护的通过结果不能替代零闪现验收。
已定位客户端内部强制显示逻辑，详见
[点歌闪现根因与失败候选记录](NETEASE_WINDOW_FLASH_ROOT_CAUSE.md)。

## 根因与复现

点歌通过网易云的命令转发进程通知已有客户端。`SW_HIDE` 只约束新进程的初始显示，
不能阻止已有主窗口再次上浮。旧保护还排除了原先可见的窗口，且只检查前台焦点，
没有处理“网易云已经盖住心隅，但焦点仍在心隅”的情况。

实际打包进程复现记录：`point-focus-0224-1a02b38611e04e10bc2165e68f7c6ec7`。
本轮只向当前选中的同一首歌发送一次请求，没有重启网易云。原生焦点保护返回成功，
但 1.4088 秒时网易云已位于心隅上方，焦点仍在心隅；6.0824 秒时网易云也获得了焦点。
该测试明确为失败，不能用早先冷启动或“打开已有应用”的测试替代。

## 修复

- 在发出点歌命令前启动保护，覆盖已经存在的网易云窗口。交接期间将官方客户端窗口隐藏，
  不调用最小化，也不调整窗口大小。
- 心隅原生窗口同时保护焦点和窗口层级：在交接期间临时置顶，最长 12 秒，结束后恢复原状态。
  引擎结束保护、用户主动切换、原窗口关闭都有清理路径；原生计时器提供独立的超时清理。
- 每次交接使用递增标识，旧请求不能解除新请求的保护。Windows 重复申请已经持有的焦点锁
  会返回失败；已有保护允许续期，并仍尝试重新取得因用户操作而释放的锁。
- 鼠标移动、普通输入不会被当成主动切到网易云。新点击其他窗口、Alt/Windows 键、
  带输入的其他应用切换会让出保护。只读取按键状态和窗口元数据，不记录输入内容。

保留 0.2.23 的宿主进程执行、内置工具身份校验、权限和幂等、实际播放证据核对。
没有修改网易云安装文件或引入调试端口。

机制依据：[LockSetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-locksetforegroundwindow)
约束前台激活；[SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)
控制可见窗口的层级，两者分别验证。
