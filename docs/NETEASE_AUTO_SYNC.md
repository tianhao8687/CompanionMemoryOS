# 网易云歌词自动同步（2026-10-15）

共享听歌优先使用系统播放时间。Windows 的网易云 3.1.41 (205529)、
Patch c6406e5 在本机提供 SMTC 歌名和控制，但不提供时间线或跳转能力。
本次增加本地播放时钟适配，中途进入也读取实际位置，不从进入时间开始猜测。
Android 沿用 MediaSession 的实际 position、updateTime、speed 和 duration；
没有可用位置时仍不把估算值冒充播放器位置。

## Windows 补充读取

仅在系统没有位置且正在播放或暂停时启用。通过当前歌曲的窗口标题定位进程，
核对其可执行文件为已安装的 cloudmusic.exe，再核对所加载 cloudmusic.dll 的完整
SHA-256、文件长度和映像大小。只接受已在本机验证的二进制：

- SHA-256：`7f667f876caf94bc3dac3b0070d3e495117005fafdcf18b6aaa51eb004edac8c`
- 文件长度：37,747,192 字节；映像大小：41,054,208 字节。
- 本地字段：播放秒数、总秒数、当前歌曲 ID。

只申请进程查询和读取权限，每次最多读取 512 字节的已知播放字段；不扫描内存，
不写入进程，不安装插件，不读取用户数据库，也不录音。未知二进制、多个目标进程、
身份变化、异常值或失败立即舍弃补充位置，已有系统控制仍照常工作。
歌曲 ID 和总时长在读取前后核对，系统歌名、歌手、专辑和播放状态也再次核对。

这是特定客户端版本的兼容适配，并非网易云公开承诺的 API。更新后须重新验证，
不能仅凭版本号或旧偏移继续使用。已知布局的研究线索来自
[CloudMusic Local API 的布局记录](https://github.com/hanbinhsh/NetEase_Cloud_Music_Local_API)，
本仓库实现独立的只读、指纹限定适配，不运行该项目的扫描、数据库或服务代码。
Windows 读取接口见 [ReadProcessMemory](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-readprocessmemory)。

## 界面行为

前台每两秒更新状态，在真实样本之间平滑推进歌词。暂停、切歌和在网易云内拖动后，
下一次状态更新重新对齐。歌词版本优先使用已验证的歌曲 ID，并仍核对标题、歌手与时长。
没有位置才出现手动对齐提示。仅能读取位置不代表能控制跳转，`controls.seek` 始终来自
系统播放器能力，不因本地时钟可读而开放拖动。

免安装版升级时，默认内置网易云连接的旧 `xinyu-engine.exe --mcp-server netease`
路径会迁到当前引擎；启用状态、逐工具权限和参数限制保留。旧待批准动作因指纹改变
不能沿用批准。自定义命令、额外参数、环境配置和 Android 本机连接不迁移。

## 陪听回复

本次明确区分分享感受与请求赏析，避免把随口喜欢变成逐词讲解和索取更多歌词。
明确的分析要求仍应完成，不以固定字数、禁止问号或删除生成文本实现自然度。
角色设定保留；自动取得的歌词仅用于显示，除用户主动分享外不注入模型。
元数据和歌词不能证明 AI 听到了唱腔、旋律或编曲，当前仍未接入歌曲音频。

评审用合成来回，标准不放入模型输入：

| 输入情境 | 要检验的行为 |
| --- | --- |
| 分享“把月光借给晚归的人”，说这句真好 | 参与欣赏，不自动变成修辞课或要求再发几句 |
| 紧接着明确问这句为什么动人、请求详细解释 | 真正展开解释，不机械限制篇幅 |
| 不同意 AI 的理解，觉得这句更孤独 | 可有自己的理解，也能回应分歧，不套用统一认错模板 |
| 单说旋律好听，未提供音频 | 可以接话；不能编造自己听到的旋律或唱法，不反复免责声明 |
| 说想起以前的人，但不想讲细节 | 不追问故事或推断分手原因 |
| 用户换话题，或结束一起听 | 不强行拉回歌词，不把活动变成永久聊天模式 |

离线测试证明上下文送达、活动范围和生成结果未被篡改，不代表上述语言表现已通过。
真实语言验收仍需要按 AGENTS.md 授权的有界模型批次。
