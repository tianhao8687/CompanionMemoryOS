## 公开角色提示词与评价方法

使用 [Bae 的公开 Persona Prompt 生成器](https://bae.ppl.studio/tools/persona-prompt)里的 **Golden Retriever BF / Any LLM**。
实际在网站选择该模板，名字改为“林舟”，用户及称呼改为“小雨”。保留生成的角色正文，去掉使用说明和广告页脚；
另外在程序的角色补充说明里注明成年、虚构、中文场景。产品原有身份真实性与同意规则仍优先。
这不是自行编写后声称来自网络的提示词，也不代表该来源的整套产品经过验证。

模拟角色为 26 岁女性“小雨”，评估这一具体伴侣视角，不把某一偏好当成所有女性的标准。
关注回应是否贴合内容、愿意继续聊、具有亲密感和自己的表达，以及分歧、称呼调整与独处时是否尊重对方。
普通提问、轻量建议、提及相关旧话题均结合语境评判，不自动扣分；不用被测模型自评分数代替人工阅读。

测试计划最多 12 轮、32 次模型调用、15 分钟，每次最多 4096 输出 token，自动重试为 0。
使用用户授权的当前程序新建测试会话与测试记忆。实际采用 deepseek-flash、温度 0.9、thinking enabled 及原记忆提取配置。
重填 Key 后用户保存的思考模式为 enabled，测试保留该实际设置；它与上一批 disabled 不同，不能当作只改代码的严格对照。
普通实例不暴露全部提取 usage，因此按 AgentLoop 上限加提取预留保守统计，未知 token 与费用不填猜测值。

如果代入小雨，我会觉得他愿意陪我，也允许我有自己的生活，整体愿意继续聊。
但我还会希望他说得更随意一点：普通分享常扩成三四段，容易像在演男友，而不是随口和我聊天。
这不是所有女性都相同的偏好；喜欢热烈、略带小说感表达的人，可能更喜欢这一版。

## 仍存在的具体问题

1. **偶尔解释自己遵守了什么。** 红薯轮末尾说“这句我记下了，不算分析，算称赞”，会让伴侣感到自己正在被处理，而不是自然被回应。
2. **旧细节回扣过密。** 第一段多次提红薯；拥抱后又切回薄荷。记得内容是优点，是否该在这一刻提起仍不够稳定。
3. **未提供的数字被补写。** 用户只说被同事打断“好几次”，回复改成“三次”。这不是风格偏好，应按证据准确性问题记录。
4. **存在一个可见的多余转义。** 偏好确认轮的“帮我想想”两侧出现多余反斜杠；原始回复与保存结果保留，未通过后处理删掉来美化成绩。

以上说明该配置尚未达到“成熟、稳定、自然的男友”质量标准。没有把功能测试通过等同于所有语言质量通过，
也没有在测试中反复改提示词、删失败轮次或只挑最好的一次展示。
