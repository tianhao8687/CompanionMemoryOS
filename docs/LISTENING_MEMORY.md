# 陪听共同经历：0.2.17（20）

2026-10-15。陪听分享写入现有 `SHARED_MOMENT` 记忆，使用原有 SQLite、来源 ID、
版本链、保留周期、召回与遗忘能力；没有新增记忆数据库、音频模型或提取模型调用。

## 记录与召回

在用户主动进入「一起听」、网易云报告正在播放且最近五秒内有有效状态的条件下，
对明确关联当前歌曲的个人分享建立记忆，例如「毕业那天我一直听这首歌」。
记录保留完整用户原话，歌曲、歌手、专辑与观察时间放在单独的播放器来源字段。
不改写原话，不推断歌词人物就是用户，也不根据一次播放推断长期喜好。

普通点歌、状态轮询、引用歌词、假设、他人陈述、疑问和无关聊天不会触发这项自动关联。
用户明确不希望记录时不建立歌曲共同经历。没有确定对象的「喜欢这首」不直接写入
长期偏好画像；有有效歌曲观察时，其原话与歌曲关联保存在共同经历中。
这是保守的本地文字识别，不能保证识别所有隐含表达；现有普通聊天记忆流程继续运行。

在新对话中提到歌名可以检索共同经历；再次陪听并问「这首歌让我想起什么」时，
用当前歌曲补充检索词，用户消息本身保持原文。召回只提供有证据的记录，最终自然语言
如何表达仍由用户配置的模型完成。只播放或静默听歌不会自动生成纪念记录。

## 生命周期与归属

- 同一个请求重试不会重复记录，也不会把旧分享重新绑定到已经切换的歌曲。
- 同一次陪听、同一首歌的明确「刚才说错了／更正一下」沿原记忆形成新版本。
  现有记忆编辑接口也可以更正；更复杂或跨歌曲的指代不猜测目标。
- 「忘记某首歌的事」可以匹配共同经历标题；遗忘会沿原有来源链处理原话及依赖回复。
- 删除来源、撤回来源授权、不再引用来源，都阻止该共同经历再次进入模型。
  应用在候选排名和提示词生成前应用现有来源限制，避免只隐藏原话却留下衍生记忆。
- 关系与用户作用域保持原样，只将对话范围提升至同一关系。另一对话不会自动继承
  仍在其他对话进行的陪听状态。
- 原话和播放器观察在模型上下文中分别标注，不证明收到歌曲音频或现实中与用户见面。

播放器快照在进入记忆数据库事务前获取，并在当前请求结束后清除；不会在写入锁内
请求播放器或获取界面操作锁。记忆默认显著性为 0.6，不因发生过播放而强行置顶。
