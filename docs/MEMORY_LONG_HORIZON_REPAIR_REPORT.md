# 长历史记忆与耗时修复

2026-09-25：耗时与记忆处理链路已修复，已完成 200 轮回归、40 轮新故事和 8 轮对照。程序已用最终代码重启，原 Key 自动恢复，本地向量服务 ready。真实生成仍有附带事实错误和一次跑题，不能将整轮语言质量判为全通过。

## 已实现的改动

- 一次同步聊天复用一个 SQLite 连接，保持原有事务提交、回滚边界。模型网络等待不持有写事务。连接不跨线程共享，已结束请求的复制上下文不会复用失效连接。
- 向量索引先比较缓存摘要，只对新增或内容变化的原话做来源检查和编码；临时状态读取只校验所需的关系动态证据。
- 模型把新话题错误挂到旧事件、或把真实用户 ID 作为普通实体引用时，单独丢弃无效提案，其余有效提案继续处理。解释失败有明确诊断回执，聊天成功不再等同于解释成功。
- 遗忘命令支持引入语和后续说明；覆盖没有结构化卡片的原始记录以及相关回复、向量。“不要忘掉”、条件句和转述不触发删除。
- 改期产生的待办按原事项主题关联，明确取消会同步关闭匹配事项，并保留最新更新来源。检索旧安排和旧预算时补取相关新版本原话。
- 多人问题补取各人的来源证据；明确点名旧值、同一情境的偏好更新接入既有版本链。补取仍检查身份、会话、现实层、时间、授权与遗忘限制。
- 即时写作和计算请求不继续充当跨回合待办。“写一句简短的话”不再被当作条件句，“给同事写备注”也识别为当前请求。仅在追问实际旧回复时配对取回，避免无关旧回答挤掉当前事实。
- 后续复测还补齐了无卡片的原话更新、“不做/去掉”订单项目、异名事件的匹配，以及新偏好标题仍残留旧值的问题。同地点另一个活动保持独立。
- 提示中明确区分计划、探访和实际交接，不从余额猜报价，不把想象中的身体动作或共同经历当历史事实。没有添加固定提问配额或要求角色一味让步。

## 仍然存在的限制

- 模型仍会在正确主答案后补出不可靠的细节。N024 擅加接送细节，N027 已算出余额 36、烫金 30 却又称“不够”，N039 把重新告知的新位置说成“没变过”。这些保留为失败，不用主要数字正确抵销它们；本轮也没有用自动重试挑一个更好的回复。
- 遗忘目前按整条来源和依赖清理。它阻止旧事实从派生回答复活，但会连带移除同条回复中的其他内容；N008 / N035 展示了这个粒度限制。没有从测试导出里把已经删除的回复重新塞回程序。
- 200 轮是第一版修复回归，之后又根据失败修正并运行 40 轮和 8 轮；没有宣称最终源码重新完整跑过 200 轮。最终源码另用原 200 轮数据的只读备份完成本地性能复核。
- 这是同日长历史与跨会话/重启测试，不是实际数周相处、数千轮规模或多人并发验收。正常分歧、反问和不同审美不作为失败。
