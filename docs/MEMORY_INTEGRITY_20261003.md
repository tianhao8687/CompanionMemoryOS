# 记忆读写完整性测试与根因修复

日期：2026-10-03（Asia/Shanghai）。本轮使用 Python 3.12.14、新建合成数据库及隔离应用进程。
没有读取日常数据库，没有调用远程真实模型，没有上传 GitHub 或触发打包。

## 验收范围

检查存储返回值、SQLite 最终记录、证据与版本链、实际召回结果，以及真正发给主模型的输入。
不把“数据库写进去了”“检索到了候选”或“助手回复非空”当作完整记忆读取成功。

- 并发重复写入、连续覆盖、单一当前版本与完整版本链。
- 写入、更正、候选确认与遗忘/清除的竞争条件。
- 到期记录、来源同意失效、新授权同文陈述的重新保存。
- 普通召回、状态查询、用户画像的读取一致性。
- 跨会话短文及长文首部、中部、尾部的原文读取、来源 ID 与精确偏移。
- 跨用户/关系隔离、遗忘、错误匹配反馈及禁止引用。
- 索引发布故障的事务回滚、多进程竞争、未提交事务中断后的恢复。
- 真实 HTTP 聊天、流式完成、真实重启和 Edge 控件交互。

## 根因与修复

| 问题 | 根因 | 最终修复 |
| --- | --- | --- |
| 同文并发入库产生两条记录，同一事实出现两个当前值 | 去重查询、读取旧版本和发布新版本不在同一写事务 | `remember` 在取得 SQLite writer slot 后完成检查和写入；底层创建也保持原子性，版本时间在取得锁后采样 |
| 遗忘后被在途更正或确认复活；来源清除后出现新派生记录 | 在等待写锁前读到了仍有效的旧状态 | 更正和确认先取得写事务，再重读目标；来源校验与新记录发布保持原子性 |
| 新陈述错误复用已过期或来源失效的旧记录 | 去重仅看状态和内容，遗漏有效期/来源资格 | 去重排除过期及失效来源；过期状态按现有生命周期转移，新来源建立自己的证据链 |
| 普通召回、状态查询与画像返回不同的有效事实 | 有的读取入口仅检查 `active` 标记，依赖后台清理已执行 | 共用同意、保留期限、来源存在性和来源同意检查；画像使用与普通召回一致的有效版本过滤，审计列表仍可检查历史记录 |
| 已检索到的交付信息没有进入模型输入 | 将“匹配分不足以直接断言”混同为“原文不可阅读” | 增加 `source_context` 用途，允许合格的弱匹配原文供模型阅读，保留原始分数、说话人、原文和来源；不把它升级为确定事实 |

`source_context` 只适用于开放式原话搜集、直接回答或任务处理，且没有状态冲突或歧义。
弱匹配还必须具有多个互不重叠的字面匹配片段；同一个短词的重叠中文 n-gram 不能重复计数。
这使用现有分词规则，不新增物件、人物、主题或问句词表，不降低原有匹配与断言阈值。
用户的禁止引用反馈仍优先；该用途受上下文预算约束，不自动生成回忆拍，也不能用于主动触达。
压缩到经历或关系时按无声影响处理，不能自动升级成明确回忆。

完整回归曾抓到本轮引入的一项缺陷：最初允许所有弱候选进入阅读上下文，使虚构故事和
无关物件出现在复合事实题里。保留了原测试和失败证据，补上上述独立字面线索条件后复测。
没有删除负例、改写原题、提高测试预算或改用期望答案喂给被测模型。

SQLite 原始记录及证据/版本链继续作为事实来源。没有引入第二套偏好数据库、永久 LISTEN
模式、固定提问额度，或通过回复后处理制造通过结果。

## 并发与故障恢复

- 单元专项中，8 个线程累计 128 次修订。重开数据库后恰好一个当前版本，全部修订可沿
  链遍历，版本时间连续；遗忘当前版本后，旧版本不复活。数据库完整性和外键检查通过。
- 注入索引发布异常时，正文、旧版本状态、证据及 FTS 统一回滚。
- 独立耐久性批次：`memory-durability-d5b514eb-4c6c-43cd-a072-005a970bf959`。
  4 个真实 Python 进程竞争写入 100 个修订，得到一条长度为 100 的版本链和一个当前值。
- 同一批次仅终止脚本自己启动的写入子进程。终止点在事务已写入但尚未提交时，另一个
  连接读不到未提交值；重新打开数据库后没有残留半条记录，证据、FTS、外键及完整性通过。
  这是进程中断恢复测试，没有模拟机器断电或存储硬件故障。
